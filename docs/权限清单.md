## 一、用户与角色总览

**概念区分：** 用户 = 谁（登录账号的主体身份）；角色 = 能干什么（权限集合）。本系统共 **3 类用户、4 个角色**。

### 1.1 用户类型（账号主体）

| 用户 | 说明 | 登录方式 | 默认持有角色 | 第一阶段是否开放 |
| --- | --- | --- | --- | --- |
| 学生 | 使用实验室的在校学生 | 手机号验证码（免注册，首次登录自动建档） | 学生 | ✅ |
| 老师 | 实验室授课老师 | 手机号验证码（免注册，首次登录自动建档） | 老师 | ✅ |
| 管理员 | 实验室审批、场地与配置的统一管理人员 | 账号密码（管理员后台批量导入建档） | 管理员 | ✅ |

### 1.2 角色定义（权限集合）

| 角色 | 角色描述 | 核心诉求 | 权限范围 | 挂载用户 |
| --- | --- | --- | --- | --- |
| 学生 STUDENT | 使用实验室的在校学生 | 便捷预约场地并查看本人记录 | 查看场地，提交单次或周期预约，查看、取消本人预约，按预约签到签退；预约仅经管理员一级审批；不可访问系统管理后台 | 学生 |
| 老师 TEACHER | 实验室授课老师 | 为实验课快速完成场地准备 | 查看场地，提交单次或周期预约，查看、取消本人预约，按预约签到签退；与学生使用同一管理员一级审批链，无额外初审或背书环节 | 老师 |
| 管理员 ADMIN | 实验室业务管理人员 | 场地台账、维修与预约审批统一管理 | 场地台账与维修时段维护、全部场地预约查询与一级审批、场地使用记录与统计、基础数据维护、操作日志查询（仅业务模块日志）；受管理员数据范围约束 | 管理员 |
| 运维管理员 OPS_ADMIN | 系统级运维人员，**最高级运维角色**（实施层增补，超出 PRD V1.8 范围） | 系统最终兜底账号，保障系统可观测、可配置、可审计、可处置 | **身份本质**：独立预置角色，仅通过初始化 SQL 预置，页面不可创建、编辑或转授。**权限范围**：仅绑定 system 模块权限和 system% 菜单，不参与场地、预约、物料等业务流程，不受数据范围约束；系统管理功能（用户/名单/组织/角色/数据范围/参数配置）自 2026-10-20 起为其专属 | 管理员（仅 SQL 预置账号 opsadmin） |

### 1.3 用户 ↔ 角色挂载规则

- 学生/老师/管理员：原则上用户与角色一一对应，建档即持有，不可转授他人；唯一例外为老师账号可经用户管理页叠加绑定管理员角色（2026-10-20 起，绑定/解绑由运维管理员操作且调用方须全校写），多角色用户登录默认以主身份角色为活动角色，可在页面上切换身份视图；切换活动角色时服务端必须校验用户实际持有该角色。
- 运维管理员：**唯一不可页面创建的角色，仅通过初始化 SQL 预置**（预置账号 opsadmin）；普通管理员无法通过任何页面或接口创建、编辑或提升账号为运维管理员；账号主体为管理员用户类型（账号密码登录、会话 8 小时）；其角色权限绑定锁定不可页面调整，其余 3 个预置角色的权限绑定可由运维管理员在角色权限页整集替换；系统管理功能整体归其专属（2026-10-20 起），普通管理员仅保留操作日志页（仅业务模块日志）。

### 1.4 身份认证规划

- **一期（本期）**：自建账号体系（账号密码 + 手机号验证码），快速上线不依赖外部平台；
- **二期（预留）**：校园 SSO 统一身份认证（首选）> 飞书免密登录（从飞书工作台一键进入 Web 应用，自动完成身份识别）；
- 人脸识别为全局可开关的可选登录方式，不得作为唯一登录手段。

## 三、数据范围规则

- **学生**：仅本人预约与使用记录、本人被委派的物料代领原申领及本人通知；场地目录按启用、可见和可约状态查询，代领按 `delegate_student_id`、通知按 `recipient_user_id` 强制本人过滤。
- **老师**：本人数据 + 所授课程关联数据（课程名单内学生的场地使用概览）；本人预约的提交、取消、签到和签退按单据归属校验。物料申领、预设方案和通知另按 `applicant_id/owner_teacher_id/recipient_user_id` 强制本人过滤，不因持有列表权限而读取他人数据。
- **管理员**：按归口部门划分数据范围；物料业务另以 `stock_location_admin` 限定实际库位操作，查看完整申领单不代表可操作其他库位：
  - 设备处管理员：全校场地与预约数据；
  - 学院管理员：本学院实验室及配套数据；
  - 跨归口数据只读不可操作。
- **运维管理员**：不受部门数据范围约束，无需登记范围行，面向系统、人员和权限管理；不持有场地、预约、物料等业务权限，补配库位或业务归属也不能绕过接口权限校验。

## 四、权限隔离规则

1. 所有写操作接口在服务端校验角色 + 数据范围双重权限，前端隐藏入口仅为体验优化，不作安全依据。
2. 学生、老师的预约取消、签到、签退与详情查询须校验本人归属；管理员审批还须校验数据范围、场地状态和当前单据状态。
3. 管理员操作（审批、处置、配置变更）全部写入操作日志，含操作人、时间、IP、变更前后值。
4. 登录态有效期 8 小时（学生/老师与管理员视图一致；普通用户 2026-10-20 起由 2 小时放宽），敏感操作（审批、处置）需二次输入密码确认。
5. 权限模型基于角色的访问控制（RBAC），数据权限按校区、楼栋、学院隔离。
6. 账号密码安全：长度 ≥8 位且含数字+字母，不设有效期（初始/被重置密码首登强制修改），连续 5 次错误锁定 30 分钟。
7. 一期不支持自定义角色（仅使用预置角色），不支持细粒度到字段级别的权限控制。
8. 运维管理员为最高级运维角色，仅通过初始化 SQL 预置，页面不可创建、编辑或转授；普通管理员无法通过任何接口创建或提升账号为运维管理员；其仅拥有 system 模块权限和 system% 菜单，不参与业务流程，不受数据范围约束；运维管理员账号的编辑/启停/重置仅运维管理员本人可操作（防接管守卫，普通管理员调用返回 40300）；OPS_ADMIN 角色权限绑定锁定不可页面调整（40900），其余 3 个预置角色的权限绑定可由运维管理员整集替换（system:role:assign，仅绑运维管理员）。
9. 系统管理功能（用户/名单/组织/角色/数据范围/参数配置）自 2026-10-20 起整体划归 OPS_ADMIN 专属；管理员仅保留操作日志页，且操作日志仅可见业务模块日志（module_code 不含 system/auth），系统管理类日志归运维管理员专属审计。预约限制页面与接口 2026-10-21 下线，资格冻结表保留供预约模块使用。
10. item 功能权限与库位操作资格分离：ADMIN 的固定资产编辑与维修切换、审核、实发、归还、移动发出/接收及复核须实时校验库位关系；在库 SCRAP/ADJUST 和在途核销须另一名同库位管理员复核。TEACHER 的申领、方案、通知、助理授权与委派逐接口校验本人归属；STUDENT 的代领接口逐接口校验被委派归属，全部角色的通知查询与已读均校验 `recipient_user_id = 当前用户`，OPS_ADMIN 无 item 权限，均不得通过直接调用 API 绕过限制。

## 五、审批链速查

### 5.1 场地预约审批

| 申请类型 | 申请人类型 | 审批链 |
| --- | --- | --- |
| 单次预约（含跳选拆分单） | 学生 / 老师 | 提交 PENDING → 管理员一级审批 → APPROVED / REJECTED |
| 周期预约 | 学生 / 老师 | 提交周期规则 PENDING → 管理员一级审批 → APPROVED / REJECTED；批准后按规则展开预约单 |

状态机：`PENDING → APPROVED / REJECTED`；`PENDING / APPROVED` 在有效条件下可进入 `CANCELLED`。已批准预约签到后派生 `IN_USE`，签退或超过 `end_at + 2h` 后派生 `FINISHED`；派生阶段不替代审批状态。提交与批准均校验 1–12 节次、开放窗口、场地状态、维修重叠与占用冲突，跳选按连续节次段拆单。
