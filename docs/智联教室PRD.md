### 1.2 涉及业务范围

本系统覆盖高校实训室与专业实验室的**设备资产全生命周期管理**，业务范围包括：

- **管理对象**：
  - 校内实训室与专业实验室（电子实验室、物理实验室、化学实验室、计算机机房、设计类实验室等）；
  - 可借用器材：示波器、万用表、信号源、3D 打印机、激光雕刻机、光谱仪、高速相机、实验台位等；
  - 实验室配件耗材（电阻电容、芯片、焊锡、烙铁、示波器探头、测试线等），按库存数量模型管理；
  - 实验室场地与工位（学号—工位固定绑定）。
- **用户对象**：学生、老师、老师助理（学生兼任，经老师授权代办物料领还）、管理员（统一承担审批、督办、台账、配置职能）；
- **业务范围**：
  - **器材管理**：实验室与器材台账、按价值分级的在线预约与审批（**学生借用须经老师审批**）、借出/归还页面确认（强制外观照留痕，扫码核验二期预留）、超期未还分级督办、损坏异常状态管理；
  - **场地管理**：实验室整间场地时段预约（排他占用、与课表冲突检测、**学生申请须经老师背书**）、场地使用台账与教室使用表；
  - **物料管理**：配件采购入库、定额领用（超定额老师签批）、贵重/危险耗材双人签字、安全库存预警、库存盘点与月报；
  - **运行保障**：三级保养体系（日常/周期/深度）、报废四态流转（申请→技术鉴定→审批→处置销账，含数据擦除确认）；
  - **课程表集成**：实验室排课 Excel 批量导入，用于场地预约冲突检测与教室使用表生成。
- **对接预留**：与学校统一身份认证（SSO）、校级资产系统、教务排课系统的对接能力预留；一期课表采用 Excel 导入轻量化方案。

涉及部门：教务处（课表数据提供方）、信息技术中心（技术支持；电脑/多媒体类设备归口）、后勤资产处（桌椅家具类归口）、各学院教学办（实验室与专业器材自管，系统主要使用方）。

> **多归口现状说明：** 校内设备无统一管理部门——电脑类设备由信息技术中心管理，桌椅板凳等家具由后勤资产处管理，专业实验器材由各学院自管。系统不强求合并归口，通过 `owner_dept` 字段支持多部门并行资产管理（仅作为资产归属与统计维度）。

**业务范围明确边界（V1.4 重要调整）：**

- **不做设备运维**：本系统**不包含**扫码报修、故障工单流转、维修派单/验收、教室巡检、6S 评分、维修知识库、维保到期预警等运维功能；设备损坏的**维修执行走线下流程**，系统仅负责状态变更（IDLE↔MAINTAINING↔SCRAPPED）、损坏记录留痕与处理结果登记；
- **不纳入**：不改造、替换实验室原有硬件设备；
- **不替代**：不替代学校现有教务排课系统、校级资产系统、后勤综合报修系统；V1.4 通过 Excel 导入实现课表集成的轻量化方案，不做排课逻辑本身。

## 二、需求概述

### 2.1 业务背景

#### 2.1.1 当前业务现状与问题

我校各学院实训室与专业实验室的设备、器材、物料管理仍大量依赖纸质登记、微信群协调与人工记忆，普遍存在以下痛点：

1. **器材账实不符**：器材借用靠纸质登记本，借出去向不明，归还状态无凭据，损坏责任追溯困难；
2. **预约靠人工协调**：贵重仪器使用靠微信群/口头约定，时段冲突频发，审批无记录、无凭据；
3. **物料去向不明**：耗材领用无定额、无登记，库存亏空往往到期末盘点才发现；
4. **保养报废不规范**：设备保养无计划、无记录；报废凭经验直接处理，缺技术鉴定、审批与数据擦除环节；
5. **数据孤岛**：实验室按学院分建、设备多归口管理，缺乏统一数据视图支撑管理决策。

#### 2.1.2 项目来源与定位

本项目由学生竞赛《智联教室》方案演进而来。经 V1.4 定位调整，**剥离教室设备运维方向，聚焦实验室设备资产的全生命周期管理**（台账 → 预约 → 借还 → 物料 → 保养 → 报废）。

**项目定位：**

- **轻量化实验室设备管理平台**，一期采用**独立部署模式**（自建账号体系 + 标准数据库 + 一套**三端合一响应式 Web 应用**（PC 优先，自适应手机浏览器），前后端不分离、后端模板渲染），不依赖任何第三方平台生态；
- 系统只做业务记录、流程流转、状态管理与统计分析；**设备维修等现场执行工作走线下流程**，业务管理制度仍需学校线下配套执行，系统不能替代校内管理制度；
- **不替代**学校现有教务排课系统、校级资产系统、后勤综合报修系统，仅预留对接扩展接口；
- **架构预留飞书接入能力**：认证、消息、存储三层接口抽象，二期可无缝接入飞书生态；
- 一期范围限定为试点学院/实验室，后续迭代推广至全校。

#### 2.1.3 业务目标（可量化）

|目标|衡量指标|目标值（一期）|
|---|---|---|
|老师器材预约响应|老师预约普通器材自动通过|即时|
|学生借用审批|学生申请到老师审批结果平均时长|≤ 4 小时（工作时段）|
|高价值器材审批|管理员 PENDING 到审批结果平均时长|≤ 2 小时（工作时段）|
|场地预约审批|提交（学生含老师背书环节）到审批结果平均时长|≤ 24 小时（工作时段）|
|器材超期未还率|超期未还记录 / 全部使用记录|≤ 3%|
|器材完整归还率|（已归还+完好）/ 全部使用记录|≥ 95%|
|使用留痕覆盖率|有借出/归还照片的使用记录占比|100%（强制拍照）|
|场地使用率|已约时段 / 开放时段|≥ 40%（试点期参考值）|
|库存预警处理及时率|安全库存预警到补充入库|≤ 5 个工作日|
|保养计划完成率|已执行 / 计划保养任务|≥ 95%|

#### 2.1.4 业务名词说明

|业务名词|说明|
|---|---|
|实验室（实训室）|同一类物理空间的不同称谓：教学计划内多称"实验室"，技能训练场景常称"实训室"；系统内统一以 `tab_lab` 建模|

|老师助理|经老师授权的学生，在授权范围与有效期内代办物料领用与收齐回库登记|
|工位|实验室内最小管理颗粒，学号—工位固定绑定|
|三级保养|日常保养（每次课后）/ 周期保养（每周）/ 深度保养（每学期）三级设备保养制度|
|定额领用|单次实训课物料领用的标准数量，超定额需老师签批|
|双人签字|贵重/危险耗材领用时经办人+管理员双人确认签字|
|多维表格|飞书提供的在线结构化数据表格，二期可选对接用于数据同步|
|SSO统一身份认证|学校统一的单点登录体系，用于校内账号一键登录|

### 2.2 用户与角色

**概念区分：** **用户 = 谁**（登录账号的主体身份）；**角色 = 能干什么**（权限集合）。本系统共 **3 类用户、4 个角色**，用户与角色按固定规则挂载，详见下文。

#### 2.2.1 用户类型（账号主体）

|用户|说明|登录方式|默认持有角色|第一阶段是否开放|
|---|---|---|---|---|
|学生|使用实验室的在校学生|手机号验证码（免注册，首次登录自动建档）|学生|✅|

> **用户 ↔ 角色挂载规则：**
> - 学生/老师/管理员：用户与角色一一对应，建档即持有，不可转授他人；
> - 老师助理：**唯一可动态授予/回收的角色，仅可附加在"学生"用户上**；授权生效期间该学生同时持有「学生 + 老师助理」两个角色，授权到期或被撤销后自动还原为纯学生；老师、管理员用户不可被授予助理角色。

> **身份认证规划**：
> - **一期（本期）**：自建账号体系（账号密码 + 手机号验证码），快速上线不依赖外部平台；
> - **二期（预留）**：校园 SSO 统一身份认证（首选）> 飞书免密登录（从飞书工作台一键进入 Web 应用，自动完成身份识别）；
> - 人脸识别为全局可开关的可选登录方式，不得作为唯一登录手段。

### 2.4 需求价值

1. **账实相符**：器材台账、预约、借还、报废全链路线上化，账实一致可查；
2. **责任可溯**：器材借出/归还全程强制拍照留痕，纠纷有据可依；
3. **管理提效**：预约自动冲突校验、老师预约免审批、学生借用在线审批、贵重超时自动通过，减少人工协调；
4. **支撑决策**：器材利用率、场地使用率、库存状态多维度看板一屏统揽；
5. **降低门槛**：一套响应式 Web 全覆盖，PC 与手机浏览器打开即用，无需下载 APP；
6. **合规可控**：照片数据防删改、操作日志全覆盖，满足校内审计要求。

### 3.2 核心业务主流程

```Plain Text
# 流程一：器材借用申请与审批流程（V1.5 调整）
学生/老师 选择目标实验室 → 浏览器材列表 → 选择器材与时段 → 提交预约申请
  ↓
按申请角色分流：
├─ 老师申请 → 系统判断器材价值分级
│   ├─ NORMAL（普通器材，单价 < 5000 或不在高价值清单）→ 直接 APPROVED
│   └─ VALUABLE（贵重器材）→ PENDING_ADMIN → 管理员审批（通过/驳回）
└─ 学生申请 → PENDING_TEACHER → 推送老师待审批
    ↓ 老师审批（4 小时未处理催办；超 24 小时未处理推送管理员可代批）
    ├─ 驳回 → REJECTED，填写驳回原因，通知学生
    └─ 通过 → 系统判断器材价值分级
        ├─ NORMAL → APPROVED
        └─ VALUABLE → PENDING_ADMIN → 管理员审批（通过/驳回）
            ↓
管理员审批（通过/驳回）
  ├─ 通过 → APPROVED，推送申请人
  └─ 驳回 → REJECTED，需填写驳回原因

# 流程二：借出与归还（页面确认，强制拍照留痕）
申请人按预约时段到实验室，在借用单上确认借出 → 强制上传借出外观照 → CHECKED_OUT（器材 IN_USE）
  ↓
使用完毕 → 在借用单上确认归还 → 强制上传归还外观照 → 登记器材状态
  ├─ GOOD（完好）→ RETURNED，器材恢复 IDLE
  └─ DAMAGED（损坏）→ 必填损坏描述 + 损坏部位照 → RETURNED
      ↓
      器材状态立即置 MAINTAINING → 推送管理员与申请人（仅知悉，不生成线上工单）
      ↓
      管理员线下安排维修 → 系统中登记处理结果
        ├─ 修复 → 器材恢复 IDLE
        └─ 无法修复 → 发起报废申请（走报废四态流转）

# 流程三：超期未还督办流程（定时扫描）
系统每小时扫描使用记录 → end_time < 当前时间 且状态仍为 CHECKED_OUT
  ↓
超期 1 小时：提醒申请人
超期 24 小时：升级提醒申请人、管理员
超期 48 小时：冻结该用户未来 7 天预约权限，推送管理员人工介入

# 流程四：物料代办流程（老师助理）
老师添加学生助理 → 设定授权范围（课程/实验室）与有效期 → 助理学生端解锁"物料代办"入口
  ↓
课前助理依据老师场地预约单/课程安排 → 到器材室领取物料并确认 → 领用出库登记（经办人=助理，归属=老师课程）
  ↓
课后助理收齐物料 → 回库登记（核对数量，差异需备注）→ 流水按 booking_id 关联核销
  ↓
授权到期或老师撤销 → 入口自动回收；在途未回库流水保留并由老师/管理员跟进

# 流程五：场地预约流程（V1.5 调整：学生申请须老师背书）
老师发起场地预约，或学生发起场地预约申请（用途/课程/班级/人数/时段，可勾选配套器材与物料预登记）
  ↓
├─ 学生提交 → PENDING_ENDORSE → 推送老师背书
│   ├─ 老师拒绝 → REJECTED，填写原因，通知学生
│   └─ 老师背书通过（endorse_teacher_id/endorse_time 留痕）→ 进入管理员审批
└─ 老师提交 → 直接进入管理员审批
  ↓
系统校验：实验室启用状态、人数≤容量、同日开放时段、同室时段不冲突（半开区间）、与课表不冲突
  ↓
PENDING → 管理员人工审批（学生单展示背书老师与背书意见；不适用超时自动通过；超 24 小时催办；start_time 已过自动失效）
  ↓
APPROVED → 自动为配套器材生成器材预约
  ↓
到开始时间系统自动置 IN_USE（占用状态写入教室使用表）
  ↓
超 end_time+2h 系统自动 FINISHED
  ↓
物料按实际出库核销、场地使用档案归档

# 流程六：配件物料库存流程
管理员采购入库（数量×单价）→ 库存增加
  ↓
实验课前老师（或授权助理）领用出库登记（定额内直接扣减；超定额需老师签批；贵重/危险耗材双人签字）
  ↓
课后工具/仪器配件回库（助理收齐核对）；耗材不回库仅核销
  ↓
stock_qty < safe_qty → 每日推送管理员直至补充；学期末盘点（盘盈盘亏生成 ADJUST 流水）→ 月报导出

# 流程七：三级保养与报废流程
日常保养：课后由老师/管理员在保养模块手动登记 DAILY 记录
周期保养：每周一自动生成 WEEKLY 计划 → 执行登记；逾期每日催办
深度保养：学期初管理员批量创建 SEMESTER 计划（含厂商）→ 执行登记
  ↓
器材报废：申请（状态锁定 MAINTAINING）→ 技术鉴定 → 审批 → 处置销账（确认数据擦除 → SCRAPPED）
```

**流程异常分支说明：**
- 拍照失败/模糊：支持重新拍摄，不允许跳过拍照进入下一环节；
- 网络异常：表单本地缓存，网络恢复自动重试上传；
- **预约时段冲突**：同一器材同时间段已有 APPROVED/CHECKED_OUT 预约 → 系统阻止提交并提示冲突器材与时段；
- **老师审批超时**：学生借用单 PENDING_TEACHER 超 4 小时（工作时段）→ 催办老师；超 24 小时 → 推送管理员，管理员可代批/代驳回并留痕；
- **高价值器材审批超时**：PENDING_ADMIN 超过 4 小时（工作时段）→ 自动推送提醒，超 24 小时 → 自动通过并通知申请人/管理员；
- **场地背书超时**：学生场地申请 PENDING_ENDORSE 超 24 小时 → 催办背书老师；超 48 小时未处理自动 CANCELLED 并通知学生；
- **场地审批不通过/过期**：REJECTED 留档不可编辑，改时段需新建预约单；start_time 已过未审批自动 CANCELLED；
- **归还损坏**：器材长期 MAINTAINING 未处理 → 每日提醒管理员，纳入看板异常清单。

|---|---|---|

|3|管理员|审批 VALUABLE 器材预约（4 小时工作时段反馈，超 24 小时系统自动通过）；代批超时学生借用单|
|4|学生/老师|按预约时段在借用单上确认借出，强制上传借出外观照|
|5|学生/老师|使用完毕在借用单上确认归还，强制上传归还外观照，登记 GOOD/DAMAGED|

|8|学生|提交场地预约申请 → 经老师背书 → 管理员审批|

|10|老师助理|课前按老师场地预约单/课程安排代领物料并登记出库，课后收齐物料回库登记；经办人记录为助理，归属老师课程，授权范围与有效期外不可操作|
|11|管理员|配件采购入库、库存预警处理、学期末盘点与月报导出|
|12|管理员|执行周期/深度保养计划登记，逾期处理；处理报废申请（鉴定→审批→处置销账）|
|13|管理员|通过看板监控器材利用率、场地使用率、库存与保养执行情况；督办超期未还与异常器材|

## 四、详细功能需求

### 模块一：学生视图

#### 4.1.1 器材浏览与借用申请（老师审批）

**功能说明：** 学生浏览各实验室可借用器材，在线提交借用申请；**申请须经老师审批**（V1.5 调整），普通器材老师审批通过即生效，贵重器材老师批后自动转管理员审批。

**前置条件：**
- 学生已完成身份校验（手机号验证码登录）；
- 学生无处于冻结状态的预约权限（超期 48 小时冻结规则见 4.5.3）。

**操作流程：**

|步骤|操作|说明|
|---|---|---|
|1|进入"器材预约"|按学院→实验室级联浏览，支持按器材类型/状态筛选|
|2|选择器材与时段|日历视图选择起止时段（已约时段置灰）|
|3|填写用途与审批老师|如"电子实验三-示波器使用"；审批老师默认本人任课老师，可改选其他老师|
|4|提交|系统实时校验冲突，单据置 PENDING_TEACHER 推送老师审批|
|5|查看结果|老师通过 → 普通器材即时 APPROVED，贵重器材转管理员审批（PENDING_ADMIN）；驳回需填原因并通知学生|

**业务规则（详见 4.5.2）：**
- 学生最多可预约未来 7 天内、累计 4 个时段的器材；
- 同一器材同时间段仅允许 1 条 APPROVED/CHECKED_OUT 预约，提交前实时校验；PENDING_TEACHER / PENDING_ADMIN 状态不占时段（审批通过时复查冲突）；
- 老师 4 小时（工作时段）未处理自动催办；超 24 小时未处理推送管理员，管理员可代批/代驳回并留痕；
- 贵重器材管理员审批 4 小时（工作时段）未处理自动催办，超 24 小时系统自动通过；
- 审批通过后在开始时间前 2 小时可取消（不计违约）。

#### 4.1.2 场地预约申请（老师背书）

**功能说明：** 学生可为竞赛训练、课程设计、社团实验等用途提交整间实验室的场地预约申请；**申请须经老师在线背书通过后，方进入管理员审批**（V1.5 新增，详细规则见 4.5.10）。

**操作流程：**

|步骤|操作|说明|
|---|---|---|
|1|进入"场地预约"|按学院→实验室级联浏览，显示容量与当日占用|
|2|选择时段|日历视图，已被占/已排课时段置灰|
|3|填写用途信息|用途、关联课程（可选）、预计人数、备注|
|4|选择背书老师|默认本人任课老师，可改选；提交后单据置 PENDING_ENDORSE 推送老师|
|5|查看结果|老师背书通过 → 进入管理员审批（PENDING）；拒绝需填原因并通知学生|

**业务规则：**
- 学生场地申请经背书与管理员审批通过后，按预约时段使用实验室；
- 背书老师 24 小时未处理自动催办，超 48 小时未处理单据自动 CANCELLED 并通知学生；
- **学生单不可勾选配套器材与物料预登记**（避免绕过器材借用的老师审批流程）；学生使用器材须按 4.1.1 单独提交借用申请。

#### 4.1.3 借出与归还（页面确认，强制外观照留痕）

**功能说明：** 学生按预约时段到实验室，在借用单上确认借出，使用完毕确认归还并登记器材状态；借出与归还均**强制上传器材外观照**，作为责任划分依据。（扫码核验为二期预留能力，一期通过页面确认完成。）

**操作流程：**

|步骤|操作|说明|
|---|---|---|
|1|打开本人借用单，点击"确认借出"|系统校验当前时间在预约时段内且状态 APPROVED|
|2|拍摄借出外观照|强制 ≥1 张、≤3 张；模糊照片不通过校验|
|3|提交借出|预约置 CHECKED_OUT，器材 IN_USE|
|4|使用完毕打开借用单，点击"确认归还"|系统提示剩余预约时段|
|5|拍摄归还外观照并选择器材状态|GOOD 完好 / DAMAGED 损坏（损坏必填描述 + 损坏部位照）|
|6|提交|GOOD → 器材恢复 IDLE；DAMAGED → 器材置 MAINTAINING 并推送管理员（详见 4.5.3，不生成线上工单）|

**业务规则：**
- 照片提交后不可删除，修改需留痕；
- 超期未还按 1h/24h/48h 分级提醒，48 小时冻结未来 7 天预约权限；
- 借出/归还照片默认保留 1 年，与使用记录关联可查。

#### 4.1.4 我的预约与使用记录

**功能说明：** 学生查看本人预约单与历史使用记录（含借出/归还照片、器材状态登记结果）。

**业务规则：**
- 学生只能查看本人记录，**不能查看他人**；
- 展示本人预约权限状态（正常/冻结中及解冻时间）；
- 记录保留周期与学校档案要求一致，默认 3 年。

#### 4.1.5 助理物料代办（老师助理专属）

**功能说明：** 经老师授权的学生助理（如课代表、实验小组长），在授权范围与有效期内，代老师完成实验物料的**课前领取登记**与**课后收齐回库登记**。助理不新增独立账号，被授权后学生端首页自动出现"物料代办"入口，授权失效后入口自动回收。

**前置条件：**
- 当前登录学生已被任一老师添加为授权助理，且授权在有效期内；
- 授权范围（指定课程/实验室）覆盖本次代办的物料所属实验室。

**操作流程：**

|步骤|操作|说明|
|---|---|---|
|1|进入"物料代办"|展示本人在授权范围内的待办清单：老师场地预约单（含物料预登记清单）、课程领用安排|
|2|选择待办单|查看物料明细（名称、规格、预登记数量、存放位置）|
|3|课前领取|到器材室领取后勾选确认实领数量 → 提交领用出库登记；实领与预登记不一致时填写原因|
|4|课后收齐回库|按领用清单逐项核对归还数量 → 提交回库登记；损耗/缺失需逐项备注（耗材类不回库，仅核销）|
|5|完成|流水自动关联 `booking_id` 核销，同步推送老师端知悉|

**字段定义：**

|字段名|类型|必填|说明|
|---|---|---|---|
|领用单号|系统生成|是|关联 tab_lab_material_flow|
|经办人|系统带入|是|助理本人学号/姓名（不可代他人提交）|
|归属老师|系统带入|是|授权老师，流水计入其课程|
|关联单据|系统带入|是|场地预约单 booking_id 或课程标识|
|实领/实还数量|数值|是|与预登记/领用数量比对，差异标红|
|差异说明|多行文本|差异时必填|损耗、缺失原因|

**业务规则：**
- 助理仅可代办**授权范围内**的单据，越权操作在前端隐藏、后端拦截；
- 授权到期或被老师撤销后，"物料代办"入口立即回收；在途未回库流水保留，由老师本人或管理员跟进处理；
- 每条流水同时记录助理本人与归属老师，双人可追溯，审计时责任归属于授权老师；
- 助理**不可**发起器材/场地预约、不可审批、不可查看他人记录，其余权限与普通学生一致；
- 高价值物料（`tab_lab_material.valuable=1`）领用仍需双人确认（经办助理 + 器材室管理员二次签字 `second_sign`），助理不可单独领用。

### 模块二：老师视图

#### 4.2.1 器材预约与批量代课预约

**功能说明：** 老师本人预约普通器材免审批即时生效（贵重器材进入管理员审批），额度高于学生，并支持为班级实验课一次性批量预约多件同类器材。

**业务规则（详见 4.5.2）：**
- 老师最多可预约未来 14 天内、累计 16 个时段的器材；
- **批量代课预约**：一次性选择同实验室多件同类器材（如全班 40 人需 40 块万用表），系统自动拆分为多条 APPROVED（普通）或 PENDING_ADMIN（贵重）预约，共享同一 purpose；
- 批量借出/归还时老师可作为操作人代学生确认（`operator_user` 记录实际操作人）。

#### 4.2.2 学生借用审批与场地背书（V1.5 新增）

**功能说明：** 老师在线处理两类学生单据：① 学生的**器材借用申请**（审批通过后学生本人在借用单上确认借出）；② 学生的**场地预约申请背书**（背书通过后转管理员审批）。

**操作流程：**

|步骤|操作|说明|
|---|---|---|
|1|进入"审批待办"|两个页签：借用审批（PENDING_TEACHER）、场地背书（PENDING_ENDORSE），按提交时间正序|
|2|查看单据详情|学生、器材/场地、时段、用途；器材单标注价值分级（贵重单提示"批后将转管理员审批"）|
|3|通过/驳回|驳回必填原因；通过后：普通器材单即时 APPROVED，贵重器材单转 PENDING_ADMIN；场地背书通过转 PENDING|
|4|结果通知|系统推送学生审批/背书结果（含驳回原因）|

**业务规则：**
- 老师仅可处理**指定自己为审批/背书老师**的单据（学生提交时选定，默认任课老师）；
- 4 小时（工作时段）未处理 → 系统催办；借用单超 24 小时未处理 → 推送管理员，管理员可代批/代驳回并留痕（操作日志记"代批"）；
- 场地背书超 24 小时未处理 → 催办；超 48 小时未处理单据自动 CANCELLED 并通知学生；
- 审批/背书动作全部记入操作日志，老师可在"审批记录"中回溯本人历史处理单据；
- 老师审批学生借用单时，系统同步校验器材时段冲突（PENDING 期间不占时段，审批通过瞬间复查）。

#### 4.2.3 场地预约发起（V1.8 起签到签退与环境照二期预留）

**功能说明：** 老师为实验课、实训周、竞赛训练、科研活动等用途申请整间实验室的时段使用权；一期采用"预约审批后到点自动使用、结束自动完结"的轻量模式，签到签退与使用前后环境照列为二期预留能力。

**发起流程（详细规则见 4.5.10）：**

|步骤|操作|说明|
|---|---|---|
|1|选择实验室|按学院→实验室级联（可按功能区分组），显示容量与当日占用|
|2|选择时段|日历视图，已被占/已排课时段置灰；实训周可"日期区间+每日统一时段"批量建单|
|3|填写用途信息|用途、课程、班级、预计人数、备注|
|4|勾选配套器材与物料预登记|仅限本实验室内器材物料；物料超库存软警告不拦截|
|5|提交|PENDING 推送管理员审批；审批通过自动生成配套器材预约|

**使用规则：**
- 审批通过 → `APPROVED`，配套器材自动生成器材预约；
- 到 `start_time` 系统自动置 `IN_USE`（占用状态写入教室使用表），无需人工签到；
- 到 `end_time+2h` 系统自动置 `FINISHED`（`finish_mode=FORCE_FINISH`），无需人工签退；
- 配套器材未归还：签退动作取消后不再强制关联处理，器材预约按自身 4.5.3 流程走超期督办；
- 实际使用人数、使用后环境照、工位复位等字段二期启用；一期不强制留痕。

#### 4.2.4 配件物料领用登记

**功能说明：** 实验课前老师按班级批量领用物料并登记出库，课后组织回库核销（可委托授权助理代办，见 4.1.5）；**领用页逐项展示物料实时可领库存**（V1.5 新增，库存不足即时提示）。

**业务规则（详见 4.5.8）：**
- 领用登记记录领用人、数量、用途（课程名称/班级），关联场地预约单时按 `booking_id` 核销；
- **实时库存提示**：领用数量超当前可领库存时**硬拦截**（与场地预登记的软警告不同，实际出库以实时库存为准）；
- **定额领用**：单次领用超过该物料 `quota_per_session`（单次实训定额）时，须老师在领用单填写签批说明（`over_quota_note`）方可提交；
- **贵重/危险耗材**（`valuable=1`）：领用须双人签字（经办人 + 器材室管理员 `second_sign`）；
- 耗材类领用后不回库仅核销；工具/仪器配件类课后归还回库，差异需备注；
- 本人可在记录中查看名下全部领用/回库流水（含助理经办部分）。

#### 4.2.5 工位学号绑定与课中工位状态上报

**功能说明：** 工业软件类实训室按"学号—工位固定绑定"入座，老师可维护本班绑定关系；课中发现工位设备异常时上报工位状态。

**业务规则（详见 4.7.2）：**
- 老师可对本班学生执行绑定/解绑（批量粘贴学号按工位号顺序自动分配）；全局一名学生最多绑定一个工位；
- 课中发现工位异常（缺件/损坏）→ 将工位置 FAULT 并填写现象 → 若工位关联主设备则该器材状态同步置 MAINTAINING → **推送管理员知悉（不生成线上工单，维修走线下）**；故障工位在后续绑定分配时自动跳过；
- 场地预约详情页展示该实验室工位看板（正常/故障/停用计数）。

#### 4.2.6 助理授权管理

**功能说明：** 老师将学生（如课代表、实验小组长）添加为**授权助理**，委托其在指定范围与有效期内代办物料领用与收齐回库登记。授权由老师直接发起、即时生效，无需管理员审核；老师可随时撤销。

**操作流程：**

|步骤|操作|说明|
|---|---|---|
|1|进入"助理管理"|展示本人已授权的助理列表（姓名、范围、有效期、状态）|
|2|添加助理|按学号/姓名搜索本校学生 → 选定|
|3|设定授权范围|勾选本人名下课程和/或实验室（可多选）|
|4|设定有效期|选择起止日期（默认本学期末，最长不超过 1 学年）|
|5|确认授权|即时生效，系统向助理学生端推送通知并解锁"物料代办"入口|
|6|撤销/调整|随时撤销授权或修改范围、有效期，变更即时生效|

**字段定义（tab_assistant_grant 授权记录）：**

|字段名|类型|必填|说明|
|---|---|---|---|
|grant_id|BIGINT|是|主键|
|teacher_id|BIGINT|是|授权老师|
|student_id|BIGINT|是|被授权学生|
|scope_type|VARCHAR(16)|是|授权范围类型：COURSE（课程）/ LAB（实验室）|
|scope_id|VARCHAR(64)|是|范围标识（课程标识或 lab_id），多条范围多行记录|
|start_time / end_time|DATETIME|是|有效期起止|
|status|VARCHAR(16)|是|ACTIVE（生效）/ REVOKED（已撤销）/ EXPIRED（已到期）|
|created_at / updated_at|DATETIME|是|创建与最后变更时间|

**业务规则：**
- 授权即时生效、即时失效，全程操作留痕（授权、修改、撤销均记入操作日志）；
- 同一学生可被多名老师授权，各授权相互独立，助理端按归属老师分组展示待办；
- 到期日 23:59 后授权自动置为 EXPIRED，入口回收；撤销即时置 REVOKED；
- 老师对助理在授权范围内的代办行为承担管理责任，可在本人记录中查看助理经办的全部物料流水；
- 授权范围仅限老师本人名下课程/实验室，老师不可为其他老师的课程授权助理；
- 助理变更（如课代表更换）由老师撤销原授权后重新添加，不支持转让。

### 模块三：管理员视图（PC 优先）

#### 4.3.1 基础数据管理

**功能说明：** 维护校区、楼栋、实验室、学院与归口部门、各类业务字典等基础数据。

**操作能力：**
- 校区/楼栋维护：一级二级空间分类，供实验室挂靠与数据范围配置使用；
- 实验室台账维护：新增/编辑/启用/停用（详细字段见 4.5.1）；
- 批量导入/导出：Excel 标准模板导入实验室、器材；
- 二维码生成（二期预留）：实验室、器材二维码自动生成，支持批量下载打印；一期不启用扫码入口；
- 字典维护：LAB_TYPE、EQUIPMENT_TYPE、EQUIPMENT_VALUABLE_TYPE（高价值清单）、COLLEGE、OWNER_DEPT、MATERIAL_CATEGORY、LAB_ZONE、BOOKING_PURPOSE、PERIOD_SLOT（节次时间表）等，全部后台可配。

**业务规则：**
- 实验室停用：反向检测该室 PENDING/APPROVED/IN_USE 场地预约生成预警清单推送管理员逐单处置（详见 4.5.10）；停用期间新预约提交被拦截；历史数据保留可查；
- 删除均为逻辑删除（status=DISABLED），保留全量历史。

#### 4.3.2 器材台账与状态管理（含损坏异常处理）

**功能说明：** 器材台账维护、状态流转管理与损坏异常的线下维修结果登记（详细字段与价值分级规则见 4.5.1）。

**核心能力：**
- 器材新增/编辑/启用/停用/申请报废；Excel 批量导入与台账导出；
- 器材状态流转：IDLE（空闲）↔ RESERVED（已预约）↔ IN_USE（使用中）→ MAINTAINING（维修中）→ IDLE / SCRAPPED（已报废）；
- **损坏异常处理（V1.4 调整：只改状态不派单）**：
  - 归还登记 DAMAGED 或工位故障上报 → 器材自动置 MAINTAINING，系统推送管理员知悉（附损坏描述与照片）；
  - 管理员**线下安排维修**，处理完毕后在器材详情页"异常处理"登记：处理结果说明、处理方式（修复/无法修复）；
  - 修复 → 器材恢复 IDLE；无法修复 → 跳转发起报废申请（走模块八四态流转）；
  - MAINTAINING 超过 3 天未处理 → 每日提醒管理员，并纳入看板"异常器材清单"；
- 器材维保到期日（warranty_end）仅作台账信息记录与列表展示，**系统不提供维保到期预警功能**。

#### 4.3.3 预约审批

**功能说明：** 统一管理三类审批待办：高价值器材预约（PENDING_ADMIN）、场地预约（PENDING，含学生背书单复核）、超时未处理的学生借用单（代批）。

**业务规则：**
- 待办列表按提交时间正序展示，支持按类型/学院/实验室筛选；
- 器材审批：通过/驳回（必填原因）；单据展示申请角色（学生/老师）与学生单的老师审批记录；PENDING_ADMIN 超 4 小时（工作时段）自动提醒，超 24 小时系统自动通过（防阻塞教学）；
- **借用单代批（V1.5 新增）**：学生借用单老师超 24 小时未审批 → 进入管理员"代批"待办，管理员可代通过/代驳回（必填原因），操作日志记"代批"，结果推送学生与原审批老师；
- 场地审批：通过/驳回（必填意见）；**学生单展示背书老师、背书时间与背书意见供复核**；**不适用超时自动通过**；超 24 小时未处理推送催办；start_time 已过仍为 PENDING 的单据自动置 CANCELLED；审批通过操作事务化并复查冲突（防并发双通过）；
- 全部审批动作记入操作日志，审批结果推送申请人。

#### 4.3.4 借还记录与超期督办

**功能说明：** 全量器材使用记录查询与超期未还的分级督办。

**功能列表：**
- 使用记录列表：按实验室/器材/用户/状态/时间筛选，查看借出/归还照片与损坏登记详情；
- 超期督办看板：超期 1-24h（已提醒）、24-48h（已升级）、>48h（已冻结预约权限）三档清单；
- 冻结管理：查看被冻结用户清单，特殊情况可人工提前解冻（记入操作日志）；
- 异常器材清单：当前 MAINTAINING 器材及持续时长，支持跳转处理登记。

#### 4.3.5 配件物料管理

**功能说明：** 配件台账、采购入库、领用审核、库存预警、盘点与月报（详细规则与字段见 4.5.8）。

**核心能力：**
- 配件新增/编辑/停用；安全库存、单次定额（quota_per_session）、贵重标记（valuable）维护；
- 采购入库：登记数量、单价、金额；
- 库存预警：stock_qty < safe_qty 每日推送，"仅看库存不足"筛选；
- **库存盘点**：创建盘点单（tab_lab_material_check）→ 按实验室逐项录入实盘数 → 盘盈盘亏自动生成 ADJUST 流水 → 盘点单归档；
- **库存月报**：按月生成各实验室出入库汇总与结存报表，支持 Excel 导出；
- 出入库流水全量查询（含经办人、归属老师、用途、关联场地单号）。

#### 4.3.6 场地使用台账

**功能说明：** 场地预约审批后的使用全过程台账（规则见 4.5.10）。

**核心能力：**
- 场地使用台账：日期、实验室、用途、班级、预计人数、实际消耗物料；签到/签退时间、使用前后环境照、实际人数列为二期预留字段；
- **教室使用表（V1.5 新增）**：以周视图合并展示各实验室的课表占用与预约占用（节次×星期网格，占用格标注课程/预约用途与申请人），支持按实验室/周次筛选与导出；供管理员与老师查看空闲时段；
- 强制取消：管理员可强制取消他人 APPROVED 预约（如学校临时征用），必填原因并推送申请人，配套器材级联释放；

- 课表反向冲突预警：课表导入/变更后与已生效场地预约的冲突清单，逐单处置。

#### 4.3.7 工位管理

**功能说明：** 工位台账、学号绑定与状态网格看板（详见模块七）。

**核心能力：** 工位新增/停用/恢复；绑定/解绑（含批量绑定）；工位状态网格（绿正常/红故障/灰停用）；工位详情（绑定学生、关联主设备、状态变更）。

#### 4.3.8 保养计划与报废审批

**核心能力：** 保养计划列表（级别/状态筛选，逾期红色高亮）与执行登记；报废待办（PENDING/APPRAISING/APPROVED 分状态）按状态执行「鉴定」「审批」「处置销账」操作，处置前强制确认存储介质数据擦除。

#### 4.3.9 数据可视化看板（驾驶舱）

**功能说明：** 一屏统揽全校实验室资产与使用情况，支持大屏视图与 PC 后台视图。

### 模块四：基础支撑

#### 4.4.1 账号与权限管理

**功能说明：** 管理账号、角色、权限。一期自建独立账号体系；二期通过认证层抽象（AuthProvider）扩展 SSO/飞书免密登录，无需改造业务代码。

**登录方式：**
- **一期（本期实现）**：
  - 账号密码登录（管理员等后台角色）；
  - 手机号验证码登录（学生、老师等用户角色，免注册，首次登录自动建档；老师助理沿用学生账号登录）；
- **二期（预留升级）**：
  - 校园统一身份认证（SSO/OAuth），校内账号一键登录；
  - 飞书免密登录：从飞书工作台点击应用直接进入 Web 应用，系统通过飞书身份凭证自动完成登录（单点登录）；
- **可选**：人脸识别登录（需明确告知、提供替代登录方式、可全局关闭；不存储人脸原始图片，仅调用比对接口）。

**账号创建方式：**
- 一期：管理员批量导入（Excel模板：姓名、角色、手机号、部门）+ 手机号验证码首次登录自动建档；
- 二期：优先通过SSO同步校级组织架构；飞书侧账号免密登录后自动关联已有账号（按手机号/工号匹配）。

**认证层预留设计要求：**
- 统一封装 AuthProvider 接口：`login()`、`getUserInfo()`、`logout()`；
- 一期实现 LocalAuthProvider，二期新增 SSOProvider、FeishuAuthProvider，配置化切换；
- 用户表预留 `sso_id`、`feishu_open_id` 字段（一期为空），二期免密登录后回填绑定。

**密码规则：**
- 密码长度≥8位，包含数字+字母；
- 90天强制更换；
- 连续5次错误锁定30分钟。

**权限模型：**
- 基于角色的访问控制（RBAC）；
- 数据权限按校区、楼栋、学院隔离；
- 操作日志全覆盖：记录操作人、时间、修改前/后内容，关键操作不可删除。

**不支持能力说明：**
- 一期不支持自定义角色，仅使用预置角色；
- 一期不支持细粒度到字段级别的权限控制。

#### 4.4.2 文件存储服务

**功能说明：** 存储器材借出/归还照片、损坏部位照片、授权证书扫描件等。场地使用前后环境照列为二期预留。一期使用本地磁盘/通用对象存储（OSS），通过 StorageService 接口抽象，二期可切换飞书云空间。

**存储约束：**
- 单张图片≤10MB；
- 图片自动压缩，压缩策略可配；
- 业务数据与图片分离存储；
- 文件访问URL统一由 StorageService 签发，业务层不感知底层存储介质，二期切换存储时历史文件URL保持可访问。

#### 4.4.3 消息推送

**功能说明：** 推送审批待办与结果、超期提醒、库存预警、保养催办等各类业务消息。一期通过站内信+短信/邮件网关实现，通过 MessageChannel 接口抽象，二期可无缝切换飞书机器人+飞书待办。

**消息类型：**
- 预约审批待办（器材/场地）与审批结果通知；
- **学生借用审批待办（推送老师）与结果通知；老师审批 4h 催办、24h 超时推送管理员代批通知**（V1.5 新增）；
- **学生场地背书待办（推送老师）、背书结果通知、背书超时自动取消通知**（V1.5 新增）；
- 管理员审批超时催办（器材 4h、场地 24h）；
- 借出/归还成功通知；超期未还分级提醒与冻结通知；
- 归还损坏知悉（推送管理员与申请人）；
- 场地审批结果、强制取消/强制结束通知、课表反向冲突预警；
- 配件安全库存预警；物料回库差异提醒；
- 保养计划生成与逾期催办；报废流程状态流转通知；
- 助理授权/撤销通知；物料代办结果知悉（推送老师）。

**业务规则：**
- 一期：站内信为主渠道（系统内消息中心），紧急类消息（超期冻结、强制取消）叠加短信通道；
- 二期：增加飞书机器人为主渠道，站内信保留为兜底；
- 消息模板统一管理，渠道无关，二期切换飞书时模板内容直接复用；
- 用户可在消息中心设置免打扰时段。

### 模块五：实验室器材管理

**模块定位：** 承载校内实训室与专业实验室的可借用器材全生命周期管理（台账 → 预约 → 审批 → 借出 → 归还 → 损坏异常 → 保养 → 报废）。以"数字化留痕 + 状态机驱动 + 看板可视化"为核心范式。**V1.4 起设备维修执行不进入系统**——器材损坏仅做状态变更、记录留痕与管理员知悉推送，维修走线下，处理结果由管理员回填。

**涉及角色：** 学生、老师（一期仅本校师生）、老师助理（学生兼任，授权范围内代办物料领用/收齐回库）、管理员（台账+审批+督办+异常处理登记+字典与高价值清单配置）。

#### 4.5.1 实验室与器材台账管理

- 一键导出当前筛选条件下的台账 Excel。

**业务规则：**
- `value_level` 变化（普通↔贵重）触发历史未结预约的重新评估（已 PENDING 转交管理员、已 APPROVED 通知申请人）；
- 状态变更为 SCRAPPED 时器材不可再被预约；
- 删除为逻辑删除（修改 `status=DISABLED`），保留全量历史。

#### 4.5.2 器材预约与审批

**功能说明：** 学生/老师在线预约器材并到时段在借用单上确认借出。**V1.5 起按申请角色分流**：老师预约普通器材免审批即时生效、贵重器材管理员审批；学生借用一律先经老师审批，普通器材老师批即生效，贵重器材老师批后再经管理员审批。

**预约单（tab_equipment_reservation）字段：**

|字段|类型|必填|说明|
|---|---|---|---|
|reservation_id|VARCHAR(32)|是|主键，如 `RV-20251007001`|
|equipment_id|VARCHAR(32)|是|预约器材|
|user_id|VARCHAR(32)|是|申请人|
|user_type|VARCHAR(16)|是|STUDENT / TEACHER|
|start_time|DATETIME|是|预约起始时段（精确到分钟）|
|end_time|DATETIME|是|预约结束时段，须 > start_time 且 ≤ start_time + 7 天|
|purpose|VARCHAR(255)|是|使用目的（如 "电子实验三-示波器使用"）|
|status|VARCHAR(16)|是|PENDING_TEACHER / PENDING_ADMIN / APPROVED / REJECTED / CHECKED_OUT / RETURNED / CANCELLED|
|teacher_approve_user|VARCHAR(32)|否|老师审批人（学生单必填，提交时选定，默认任课老师）|
|teacher_approve_time|DATETIME|否|老师审批时间|
|approve_user|VARCHAR(32)|否|管理员审批人（VALUABLE 器材填写；代批时记管理员并标注"代批"）|
|approve_time|DATETIME|否|管理员审批时间|
|reject_reason|VARCHAR(255)|否|驳回原因（老师或管理员驳回均填写）|
|cancel_user|VARCHAR(32)|否|取消人（申请人/管理员）|
|cancel_time|DATETIME|否|取消时间|
|booking_id|VARCHAR(32)|否|来源场地预约单（由场地预约自动生成时回写）|
|create_time / update_time|DATETIME|是|系统字段|

**预约提交规则：**
- 学生最多可预约未来 7 天内、累计 4 个时段的器材；
- 老师最多可预约未来 14 天内、累计 16 个时段的器材（支持批量代课班级预约）；
- 同一器材在 `[start_time, end_time)` 区间内只允许 1 条 `APPROVED` 或 `CHECKED_OUT` 的预约（系统提交前实时校验）；`PENDING_TEACHER` / `PENDING_ADMIN` 状态不占时段，审批通过瞬间复查冲突，冲突则审批失败并提示；
- 预约提交后系统按申请角色分流：
  - **老师申请**：NORMAL → 直接置 `APPROVED`，推送"预约成功"；VALUABLE → 置 `PENDING_ADMIN`，推送管理员待审批；
  - **学生申请**：一律置 `PENDING_TEACHER`，推送所选审批老师待审批。

**老师审批规则（学生单必经，V1.5 新增）：**
- 老师在"审批待办"看到指定自己审批的 PENDING_TEACHER 预约（按提交时间正序）；
- 审批操作：通过 → NORMAL 单直接 `APPROVED`、VALUABLE 单转 `PENDING_ADMIN`（推送管理员）；驳回 → `REJECTED` + 必填驳回原因 + 推送学生；
- 审批超时：PENDING_TEACHER 超 4 小时（工作时段 08:00-20:00）→ 自动催办老师；超 24 小时仍未处理 → 推送管理员，管理员可代通过/代驳回（必填原因，日志记"代批"，结果推送学生与原审批老师）。

**管理员审批规则（仅 VALUABLE 器材）：**
- 管理员在"预约审批"待办列表中看到全部 PENDING_ADMIN 预约（按提交时间正序），学生单展示老师审批记录；
- 审批操作：通过 → `APPROVED` + 推送申请人；驳回 → `REJECTED` + 必填驳回原因 + 推送申请人；
- 审批超时：PENDING_ADMIN 超过 4 小时（工作时段 08:00-20:00）→ 自动推送提醒管理员；超 24 小时仍未处理 → **系统自动通过** 并通知申请人与管理员（避免阻塞教学）；
- 申请人可在审批前主动 `CANCELLED`，已审批通过的在开始时间前 2 小时仍可取消（不计入违约）。

**批量代课预约（老师专属）：**
- 老师可一次性选择同实验室多件同类器材（如全班 40 人需 40 块万用表），系统自动拆分为多条 `APPROVED`（普通）或 `PENDING_ADMIN`（贵重）预约；
- 批量预约共享同一 `purpose`，便于追溯。

#### 4.5.3 借出与归还

**功能说明：** 申请人按预约时段到实验室，在借用单上确认借出，使用完毕确认归还并登记器材状态（扫码核验为二期预留，一期页面确认）；**损坏仅触发状态变更与推送（V1.4 调整，不再生成线上工单）**。

**使用记录（tab_equipment_usage）字段：**

|字段|类型|必填|说明|
|---|---|---|---|
|usage_id|VARCHAR(32)|是|主键，如 `UG-20251007001`|
|reservation_id|VARCHAR(32)|是|关联预约，一对一|
|equipment_id|VARCHAR(32)|是|冗余器材，便于按器材统计|
|user_id|VARCHAR(32)|是|实际使用人（与预约人一致）|
|checkout_time|DATETIME|是|借出时间（页面确认）|
|checkin_time|DATETIME|否|归还时间|
|checkout_photos|CLOB/JSON|否|借出时器材外观照片（URL 列表，强制 ≥1 张）|
|checkin_photos|CLOB/JSON|否|归还时器材外观照片（URL 列表，强制 ≥1 张）|
|condition|VARCHAR(8)|否|GOOD / DAMAGED（归还时必填）|
|damage_desc|TEXT|否|损坏描述（condition=DAMAGED 时必填）|
|damage_photos|CLOB/JSON|否|损坏部位照片|
|handle_result|VARCHAR(500)|否|管理员损坏处理结果说明（线下维修完成后回填）|
|handle_user|VARCHAR(32)|否|处理人（管理员）|
|handle_time|DATETIME|否|处理时间|
|operator_user|VARCHAR(32)|否|借出/归还确认操作人（可与使用人不同，如老师批量代借）|
|create_time / update_time|DATETIME|是|系统字段|

**借出流程：**
1. 申请人到达实验室，使用移动端浏览器打开本人借用单，点击"确认借出"；
2. 系统校验：当前时间在 `[start_time, end_time + 30分钟宽容]` 区间内 + 预约状态为 `APPROVED`；
3. 校验通过 → 强制上传 ≥1 张借出外观照（≤3 张） → 预约状态置为 `CHECKED_OUT`，创建 `usage_id`，器材 `status=IN_USE`，推送申请人"借出成功"。

**归还流程：**
1. 申请人打开借用单点击"确认归还"，系统展示当前器材剩余预约时段提示；
2. 强制上传 ≥1 张归还外观照 → 选择器材状态：
   - **GOOD（完好）** → 预约置为 `RETURNED`，器材恢复 `IDLE`；
   - **DAMAGED（损坏）** → 必填损坏描述 + 上传 ≥1 张损坏照片 → 预约置为 `RETURNED`，同时：
     - 器材 `status` 立即更新为 `MAINTAINING`；
     - **推送管理员与申请人**"器材损坏待处理"（附损坏描述与照片，仅知悉，不生成线上工单）；
     - 管理员**线下安排维修**，处理完毕后在系统中登记处理结果（`handle_result/handle_user/handle_time` 回填）：
       - 修复 → 管理员手动恢复器材 `IDLE`；
       - 无法修复 → 跳转发起报废申请（走模块八四态流转）；
     - 器材 MAINTAINING 超过 3 天未处理 → 每日提醒管理员，纳入看板"异常器材清单"。

**逾期与违约：**
- 系统每小时扫描 `end_time < 当前时间 且 status=CHECKED_OUT` 的使用记录；
- 超期 1-24 小时：站内信+短信提醒申请人；
- 超期 24-48 小时：升级提醒申请人、管理员；
- 超期 48 小时：自动冻结该用户未来 7 天的预约权限（不可预约但不影响已通过的预约），推送管理员人工介入。

#### 4.5.4 器材总览看板

**功能说明：** 管理端驾驶舱"器材总览"页签，统揽全校实验室器材使用情况。

|指标|计算口径|

#### 4.5.6 实验室场景的端到端串联

**典型场景：**

> **场景 A：学生借示波器（贵重器材，需审批）**
> 周二 10:00，计算机学院学生小王预约周三 14:00-16:00 使用电子实验室 E101 的数字示波器 EQ-OSC-003（单价 7800 元，VALUABLE）。
> - 提交预约 → 状态 PENDING，推送管理员张老师；
> - 张老师 11:30 审批通过 → 状态 APPROVED，推送小王；
> - 周三 13:55，小王到实验室在借用单上确认借出，上传 2 张外观照 → 状态 CHECKED_OUT，器材 IN_USE；
> - 16:30，小王在借用单上确认归还，上传 2 张外观照，选择 GOOD → 状态 RETURNED，器材 IDLE。

> **场景 B：学生借万用表（普通器材，免审批）**
> 同一时段学生小李预约 E101 的万用表 EQ-MULTI-012（单价 80 元，NORMAL）→ 直接 APPROVED，借出/归还同上。

> **场景 C：归还时发现损坏（只改状态不派单）**
> 周四 17:00，小王归还上周借出的示波器，拍照后发现探头线断裂 → 选择 DAMAGED，填写"探头线断裂，疑似拉扯过度"，上传 3 张损坏部位照 → 状态 RETURNED，器材立即置 MAINTAINING，管理员小陈收到"器材损坏待处理"推送；
> 小陈线下联系维修更换探头线 → 维修完成后在系统中登记处理结果"已更换探头线，恢复正常"→ 器材恢复 IDLE；
> 若鉴定无维修价值 → 小陈发起报废申请，走"申请→技术鉴定→审批→处置销账"流程。

> **场景 D：批量代课预约**
> 周五上午，王老师要为 40 名学生上电路实验课，需借用 40 块万用表 → 在老师端"批量预约"选择 E101 全部 40 块万用表，时段 09:00-11:00 → 系统自动生成 40 条 APPROVED 预约（万用表均为 NORMAL）→ 09:30 学生在借用单上批量确认借出 → 11:10 王老师逐一确认批量归还。

#### 4.5.8 实验室配件（耗材）管理

**功能说明：** 器材是可借用的整机设备（示波器、万用表），配件是实验过程中消耗或配套使用的低值物料（电阻电容、焊锡、烙铁、示波器探头等）。配件走"**库存数量**"模型而非器材的"单件预约"模型：采购入库增加库存，实验课领用扣减库存，低于安全库存自动预警。

**业务规则：**
- 配件归属某间实验室（间接归属学院），按三类管理：
  - `CONSUMABLE` 耗材：电阻、电容、芯片、导线、焊锡、保险丝等（消耗后补充）；
  - `TOOL` 工具：电烙铁、剥线钳、镊子、热风枪等（循环使用，按数量盘点）；
  - `INSTRUMENT_PART` 仪器配件：示波器探头、BNC 测试线、鳄鱼夹、电源适配器等（随仪器配套）；
- **入库**：采购入库必须登记数量、单价、金额（用于库存价值统计）；
- **领用**：实验课前由任课老师（或其授权助理）按班级批量领用登记，记录领用人、数量、用途（课程名称）；助理代办时流水同时记录助理本人与归属老师；耗材类领用后不回库，工具/仪器配件类课后归还回库（助理负责收齐）；
- **实时库存可见**：领用登记页与学生端物料页均逐项展示实时可领库存（`stock_qty` 减去已登记未回库数量）；领用数量超过实时可领库存时**硬拦截**，无法提交（区别于场地预登记的软警告）；
- **定额领用**：单次领用超过 `quota_per_session`（单次实训定额，按物料配置，可为空表示不限）时，须老师在领用单填写签批说明（`over_quota_note`）方可提交；
- **贵重/危险耗材双人签字**：`valuable=1` 的物料领用须经办人 + 器材室管理员双人签字确认（`second_sign` 记录第二签字人）；
- **库存预警**：`stock_qty < safe_qty` 时每日推送管理员，直至补充入库；
- **盘点**：创建盘点单（`tab_lab_material_check`）→ 按实验室逐项录入实盘数 → 盘盈盘亏自动生成 `ADJUST` 流水 → 盘点单归档；支持按实验室导出库存清单（Excel）用于学期末对账；
- **月报**：按月生成各实验室出入库汇总与结存报表，支持 Excel 导出。

**界面要素（管理端「物料管理」）：**
- 列表：配件编号、名称、分类、规格型号、所属学院/实验室、库存数量/安全库存、单价、最近入库时间；库存不足行红色高亮；
- 筛选：按学院 → 实验室级联筛选、按分类筛选、"仅看库存不足"开关；
- 操作：新增配件、入库、领用登记、编辑安全库存与定额、发起盘点；入库/领用弹窗均显示当前库存并校验不能扣成负数。

#### 4.5.9 分学院管理与设备多归口

**背景：** 学校实验室按学院建设，不同学院的实验室类型与器材构成差异大（电子信息学院以示波器/信号源为主，机械学院以台钳/量具为主，计算机学院以服务器/交换机为主）；同时校内设备**没有统一归口**——电脑类设备由信息技术中心管理，桌椅板凳等家具由后勤资产处管理，专业器材由学院自管。系统按"学院维度 + 归口部门维度"双线建模，尊重现有管理格局，不强行合并。

**1）分学院管理：**
- `tab_lab` 字段 `college_id`、`college_name`（所属学院，字典 COLLEGE）；
- `tab_user` 可选字段 `college_id`：管理员账号可绑定学院，绑定后管理端列表默认只显示本学院数据，可切换"全部"（需在数据范围配置中允许）；
- 器材类型字典 `EQUIPMENT_TYPE` 支持按学院配置差异项：管理员为某学院追加本学院特有的器材类型（如机械学院追加"台钳""游标卡尺"），不污染其他学院下拉项；
- 看板支持按学院对比：各学院实验室数量、器材总价值、本学期借用人次。

**2）设备多归口管理：**
- `tab_lab_equipment` 字段 `owner_dept`（归口管理部门，字典 OWNER_DEPT）：

|dict_key|归口部门|管辖范围示例|
|---|---|---|
|INFO_CENTER|信息技术中心|机房电脑、服务器、网络设备、多媒体中控|
|LOGISTICS|后勤资产处|桌椅板凳、讲台、门窗、照明、窗帘|
|COLLEGE|学院自管|专业实验器材、学院自购设备|

- `tab_user` 可选字段 `dept`（INFO_CENTER / LOGISTICS），管理员账号标记所属部门；
- 资产台账与看板均支持按归口部门筛选/分组统计；
- 归口部门为**字典配置**，若学校后续成立统一资产管理部门，仅需调整字典与器材归口字段，无需改代码；
- **V1.4 说明：** 归口维度仅用于资产归属标记与统计分组；系统已不含工单功能，不再承担按归口分流派单的职责。

#### 4.5.10 实验室（实训室）场地预约

**功能说明：** 实验室（又称实训室）作为**场地资源**对外开放预约：老师为实验课、实训周、竞赛训练、科研活动等用途申请整间实验室的时段使用权；**学生也可为竞赛训练、课程设计等用途提交申请，但须经老师在线背书通过后方可进入管理员审批**（V1.5 调整）。场地预约是"**整间排他**"模型——同一时段一间实验室只能有一个生效预约，与器材的"单件预约"相互独立，但可携带配套器材与物料清单一并申请。**V1.8 起采用轻量模式：审批通过后到点自动使用、结束自动完结；签到签退与使用前后环境照列为二期预留**（相关字段保留）。

**与器材预约的区别：**

|维度|场地预约（本节）|器材预约（4.5.2）|
|---|---|---|
|预约对象|整间实验室（tab_lab）|单件器材（tab_lab_equipment）|
|占用模型|同时段排他|同时段同一件排他|
|发起人|老师；学生（须老师背书）|学生、老师均可（学生须老师审批）|
|审批方式|学生单：老师背书 → 管理员审批；老师单：管理员审批|学生单：老师审批（贵重转管理员）；老师单：普通自动通过、贵重管理员审批|
|联动|老师单可携带器材清单、物料预登记|归还损坏触发状态变更与管理员推送|

**业务规则：**
- **发起**：老师直接发起；学生发起须选择背书老师（默认任课老师，可改选），单据先置 `PENDING_ENDORSE` 推送老师背书。填写用途（课程实验/实训周/竞赛训练/科研/其他）、课程与班级名称、使用人数、起止时段、备注；
- **老师背书（学生单必经，V1.5 新增）**：背书老师通过 → 转 `PENDING` 进入管理员审批，记录 `endorse_teacher_id/endorse_time/endorse_status`；拒绝 → `REJECTED` 必填原因推送学生；背书超 24 小时未处理催办，**超 48 小时未处理单据自动 CANCELLED** 并通知学生；
- **多日批量建单（实训周）**：用途为 `TRAINING_WEEK` 时可选择"日期区间 + 每日统一时段"（如 10-13 至 10-17 每天 08:00-17:00），提交后服务端**逐日拆分为独立的单日预约单**（共享同一 `batch_id`），每单独立走状态机（独立取消/自动完结）；**审批按批次一次完成**，逐日复查冲突——冲突的单日单独驳回并注明原因，其余通过；日期区间长度 ≤ `booking-batch-max-days`（默认 7 天），每日时段仍受同日、开放时段、最长时长约束；其余用途仅支持单日预约（多日批量建单仅老师可用）；
- **人数校验**：`expected_count > 实验室 capacity` → 提交时直接拦截，提示容量上限；
- **时段合法性**：`start_time` 与 `end_time` 必须在**同一天**且落在开放时段内（默认 08:00-21:00），不允许跨天；隔夜使用需求（如培养观察）走管理员线下审批，不开放线上；
- **冲突判定区间**：所有时段重叠判定采用**半开区间 `[start, end)`**——端点相接不算冲突（A 约 13:00-14:00，B 可约 14:00-16:00）；
- **冲突检测（提交时+审批时双重校验）**：
  0. **实验室状态校验**：`tab_lab.status = DISABLED`（已停用）→ 提交直接拦截"该实验室已停用"；
  1. 与同实验室其他 `APPROVED`/`IN_USE` 场地预约时段重叠 → 拦截；**`PENDING` 不参与冲突、不占时段**（防止恶意提交占位锁死场地）；
  2. 该实验室在 `tab_course_schedule` 有正式排课的时段 → 拦截并提示"该时段已有教学排课"；**课表经 `tab_course_schedule.lab_id` 直接关联实验室定位**；
  3. **课表换算规则**：将预约日期换算为"学期第几周 + 周几 + 覆盖节次"，与课表记录做 `week_mask` 位运算比对（第 N 周对应掩码第 N 位），仅当排课记录在该周生效才算冲突；
  4. **审批时复查**：两个同时段 PENDING 先批先得，后批的被冲突拦截；审批通过操作须事务化处理，防止两名管理员并发审批同时通过；
  5. **课表反向冲突**：课表导入/变更时，反向检测与已生效（`APPROVED`/`IN_USE`）场地预约的冲突，生成预警清单推送管理员处理（调整排课或取消场地预约）；
- **审批**：背书通过的学生单与老师单一律进入管理员人工审批，**不适用超时自动通过**；**学生单展示背书老师与背书意见供复核**；审批超 24 小时未处理推送催办；`start_time` 已过仍为 `PENDING` 的单据**自动置 CANCELLED（过期失效）**并通知申请人；**审批通过前置校验 `start_time` 未过期**（防止定时任务扫描间隙批出过期单）——已过期的单据无法通过、只能驳回；批量单（同 `batch_id`）按批次审批一次完成；
- **驳回与重提**：`REJECTED` 单据留档不可编辑；申请人修改时段后**新建预约单**重新提交；
- **配套器材**：**仅老师单**可勾选本实验室内器材清单，审批通过后系统自动为每件器材生成器材预约（继承相同时段与申请人，`booking_id` 回写来源）；**与已有器材预约冲突的单件生成失败，场地预约仍然生效**，推送申请人"5 件中 2 件未能预留，请单独协调"；归还流程复用 4.5.3。**学生单不可勾选配套器材与物料预登记**（避免绕过器材借用的老师审批流程），学生使用器材须按 4.5.2 单独提交借用申请；
- **取消级联**：场地预约单被取消（任意 `cancel_reason`）或被强制结束（`FORCE_FINISH`）时，**级联处理其名下器材预约**：未借出（`PENDING`/`APPROVED`）的一并置 `CANCELLED` 并释放器材；已借出（`CHECKED_OUT`）的保留，继续走归还与超期督办流程；
- **物料预登记**（仅老师单）：可预填本次实验预计消耗的物料（如"焊锡丝 2 卷、面包板 30 块"）；预填数量超当前库存时**软警告**（不拦截，库存可能补充）；课后按实际出库数量在领用登记时关联 `booking_id` 核销，实际消耗计入该次场地使用档案；
- **自动使用与自动完结（V1.8 调整）**：到 `start_time` 系统自动将 `APPROVED` 置为 `IN_USE`（占用状态写入教室使用表），无需人工签到；到 `end_time + booking-force-finish-hours`（默认 2h）系统自动置 `FINISHED`（`finish_mode=NORMAL`），无需人工签退；管理员可对 `IN_USE` 单执行"强制结束"（`finish_mode=FORCE_FINISH`，必填原因并推送申请人）；
- **完结时器材未归还**：场地单自动完结不影响其名下器材预约——未归还器材继续走 4.5.3 归还与超期督办流程，不受场地状态约束；
- **取消**：`PENDING`/`APPROVED` 状态且未到开始时间，申请人可取消（批量单支持整批取消或逐日取消）；**管理员可强制取消他人 `APPROVED` 预约**（如学校临时征用），强制取消必须填原因并自动推送申请人；所有取消均触发上述配套器材级联；
- **实验室停用**：实验室被停用（`status → DISABLED`）时，系统反向检测该室 `PENDING`/`APPROVED`/`IN_USE` 预约生成预警清单推送管理员——管理员逐单决定强制取消（`FORCE`）或保留至恢复启用；停用期间新预约提交被拦截（见冲突检测 0）；
- **同一申请人同时段**：同一老师同时段预约多间实验室 → 软警告"您在该时段已有其他场地预约"，不强制拦截。

**状态机：**

```
（学生单）PENDING_ENDORSE（待老师背书）→ PENDING ─┐
        ↓（老师拒绝/超48h未处理）                  │
     REJECTED / CANCELLED                          │
（老师单）────────────────→ PENDING（待审批）→ APPROVED（已通过）→ IN_USE（使用中）→ FINISHED（已结束）
                                 ↓                 ↓    （到 start_time 自动进入）   ↑（到 end_time+2h 自动完结，
                              REJECTED（已驳回）  CANCELLED                          或管理员强制结束 FORCE_FINISH）
                                 ↑            （手动/过期/强制，cancel_reason 区分）
                                 └── start_time 已过未审批 → 自动 CANCELLED（过期失效）
```

**取消原因枚举（`cancel_reason` 字段）：**

|值|含义|触发方|
|---|---|---|
|MANUAL|申请人手动取消|申请人|
|AUTO_EXPIRED|start_time 已过仍未审批|系统|
|FORCE|管理员强制取消（必填原因）|管理员|

**边界与异常处理汇总：**

|场景|处理|
|---|---|
|学生单背书超时|24h 催办背书老师；超 48h 未处理自动 CANCELLED 通知学生|
|学生单勾选配套器材/物料|不支持，学生须按 4.5.2 单独提交器材借用申请（走老师审批）|

|PENDING 占位|PENDING 不占时段，审批通过时复查冲突|
|审批并发双通过|审批操作事务化，后提交者被冲突拦截|
|课表后导入覆盖已批预约|反向冲突预警清单推送管理员|
|配套器材部分冲突|场地预约生效，失败器材推送提示|
|场地自动完结时器材未归还|器材预约不受影响，继续走归还与超期督办流程|
|预约时段已过未审批|自动 CANCELLED（AUTO_EXPIRED）|
|预计人数超容量|提交时拦截|
|物料预登记超库存|软警告，不拦截|

|实验室已停用（DISABLED）|提交拦截；停用动作反向预警存量 PENDING/APPROVED/IN_USE 预约推管理员处置|
|器材/物料跨实验室勾选|仅可选择本实验室下器材与物料，提交校验拦截|

### 模块六：实验室排课与课程表集成

> **设计动机**：实验课等正式教学排课时段，实验室不可对外开放预约。V1.4 将课程表模块收缩为**场地预约冲突检测的数据源**：管理员批量导入实验室排课表，系统在场地预约提交与审批时自动比对冲突，并提供课表变更后的反向冲突预警。

|场景|用户角色|典型操作|

|课表变更冲突处置|管理员|课表导入/变更后，查看与已生效场地预约的反向冲突预警清单，逐单处理|

#### 4.6.4 课程表 Excel 导入与手工维护

**模板格式**（`实验室排课导入模板.xlsx`）：

|labNo|teacherId|courseName|className|semester|weekday|periodStart|periodEnd|weekMask|
|---|---|---|---|---|---|---|---|---|
|E101|U-T-001|电子技术实验|电信2301|2025-秋|1|1|2|1-16|
|E101|U-T-005|电路分析实验|电信2302|2025-秋|3|3|4|1-16|

**导入流程：**
1. 管理员上传 Excel
2. 后端解析 → 逐行校验：
   - labNo 是否存在于 tab_lab
   - teacherId 是否存在且角色为老师
   - weekday ∈ [1,7]，periodStart/periodEnd ∈ [1,12] 且 start ≤ end
   - weekMask 格式合法
3. 返回解析报告：成功 N 条 / 失败 M 条（失败行附错误原因）
4. 管理员确认后批量入库；可选项"覆盖已有冲突记录"决定 UPDATE 还是 SKIP
5. 入库后触发**反向冲突检测**：与已生效（APPROVED/IN_USE）场地预约比对，生成预警清单推送管理员

**API**：`POST /api/admin/schedules/import` (multipart/form-data)
**响应**：`{ success: 248, failed: 3, errors: [{row: 5, msg: '实验室 E999 不存在'}] }`

**手工维护：** 支持按学期对排课记录手工增删改（变更同样触发反向冲突检测）。

### 模块七：实训室功能分区与工位管理

> **设计动机**：工业软件实训室按"软件为主、硬件为辅、软硬结合"建设，规范建议划分五大功能区；教学运行要求"学生按学号—工位固定绑定入座"，课后登记也以工位为最小颗粒。本模块将实验室管理颗粒度从"间"细化到"工位"。

#### 4.7.1 实验室功能分区（tab_lab 字段）

`tab_lab` 字段：

|字段|类型|说明|

### 模块八：设备三级保养与报废流程

> **设计动机**：规范要求"日常保养（每次课后，学生+老师）/周期保养（每周，管理员）/深度保养（每学期，管理员+厂商）"三级保养制度，以及"申请→技术鉴定→审批→处置销账"的报废闭环（含存储介质数据擦除）。器材报废不直接改状态，走流程化四态流转。

#### 4.8.1 三级保养体系

|级别|频次|主要内容|责任人|系统落地|
|---|---|---|---|---|
|日常保养 DAILY|每次课后|清洁工位、设备归位、断电检查|学生+老师|课后由老师/管理员在保养模块手动登记，可关联场地预约单|
|周期保养 WEEKLY|每周|设备外观除尘、线缆检查、软件环境抽检|管理员|每周一生成保养计划，登记执行结果|
|深度保养 SEMESTER|每学期|机箱除尘、系统重装还原、仪表校验、空调滤网清洗|管理员+厂商|学期初手工/批量建计划，执行登记含厂商信息|

**保养计划（tab_lab_maintain_plan）**：

|字段|类型|说明|
|---|---|---|
|plan_id|VARCHAR(32) PK|计划 ID（MP-xxxx）|

|target_id|VARCHAR(32)|对象 ID（lab_id 或 equipment_id）|
|level|VARCHAR(12)|DAILY / WEEKLY / SEMESTER|
|title|VARCHAR(128)|计划标题，如 "LB-001 第 42 周周期保养"|
|content|VARCHAR(500)|保养内容要点（按级别给默认模板，可改）|
|plan_date|DATE|计划执行日（周保养=本周五前；学期保养=指定日）|
|assignee_id|VARCHAR(32)|执行人（默认实验室保管人）|
|status|VARCHAR(12)|PENDING 待执行 / DONE 已执行 / OVERDUE 逾期|
|create_time / update_time|DATETIME|系统字段|

**保养记录（tab_lab_maintain_record）**：

|字段|类型|说明|
|---|---|---|
|record_id|VARCHAR(32) PK|记录 ID（MR-xxxx）|

|vendor|VARCHAR(64)|厂商（深度保养填写）|
|booking_id|VARCHAR(32) FK|来源场地预约（日常保养登记时可关联，可空）|
|note|VARCHAR(255)|备注|
|create_time|DATETIME|创建时间|

**自动化规则：**
- 日常保养（DAILY）：课后由老师/管理员在保养模块手动登记（可关联场地预约单 `booking_id`，可空）；
- 每周一 07:00 定时任务：为每间 ENABLED 实验室生成一条 WEEKLY 计划（plan_date=本周五），推送管理员；
- `plan_date` 已过仍 PENDING → 置 OVERDUE 并每日推送，直至执行登记；
- 深度保养学期计划由管理员在学期初批量创建（选实验室多选 + 计划日），厂商字段执行时填写。

#### 4.8.2 报废流程（tab_lab_scrap）

**规则**：器材「报废」不直接改状态，发起报废申请单，走四态流转。

```
PENDING（申请待鉴定）→ APPRAISING（技术鉴定中）→ APPROVED（已批准待处置）→ DISPOSED（已处置销账）
      ↓                      ↓                       
   REJECTED（鉴定不通过）  REJECTED（审批不通过，器材恢复原状态）
```

|字段|类型|说明|
|---|---|---|
|scrap_id|VARCHAR(32) PK|报废单 ID（SC-xxxx）|
|equipment_id|VARCHAR(32) FK|报废器材|
|applicant_id|VARCHAR(32) FK|申请人（管理员）|
|reason|VARCHAR(500)|报废原因（达到使用年限且无法修复/维修成本过高等）|
|apply_time|DATETIME|申请时间|
|status|VARCHAR(16)|PENDING / APPRAISING / APPROVED / REJECTED / DISPOSED|
|appraiser_id / appraise_time / appraise_note|—|技术鉴定人/时间/鉴定意见（APPRAISING 环节填写：是否确无修复价值）|
|approver_id / approve_time / approve_note|—|审批人/时间/审批意见|
|data_wiped|CHAR(1)|存储介质数据擦除确认 Y/N（处置前必确认；涉密介质物理销毁写入处置说明）|
|dispose_time / dispose_note|—|处置时间/处置与销账说明（资产处置单号等）|
|create_time / update_time|DATETIME|系统字段|

**业务规则：**
- 发起申请：器材状态须为 `MAINTAINING`（损坏确认无法修复）或 `IDLE`（老旧待汰换）；申请期间器材状态锁定为 `MAINTAINING`（防误借出）；
- 技术鉴定：管理员操作，填写鉴定意见 → 转 APPRAISING；鉴定不通过 → REJECTED 并恢复原状态；
- 审批：鉴定通过后管理员审批（同一人可鉴定+审批，一期不强制分离）；审批通过 → APPROVED；
- 处置销账：确认 `data_wiped=Y` 并填写处置说明 → DISPOSED，器材状态自动置 `SCRAPPED`；
- 全程推送：各状态流转通知申请人；REJECTED 必填原因。

#### 4.8.3 界面要素

- 管理端「器材管理」菜单新增「保养计划」「报废审批」两个页签：
  - 保养计划：级别筛选（日常/周期/深度）、状态筛选（待执行/逾期红色高亮）、执行登记弹窗（内容/结果/厂商/异常说明）；
  - 报废审批：待办列表（PENDING/APPRAISING/APPROVED 分状态 tag）、操作列按状态显示「鉴定」「审批」「处置销账」按钮（处置弹窗强制勾选"存储介质已擦除"）；
- 器材台账行操作「申请报废」按钮，跳转报废申请弹窗；
- 「场地管理」实验室详情新增「保养记录」区块（最近 5 条）。

#### 4.8.4 配置项

- `zlj.lab.maintain-weekly-gen`：周期保养计划生成时刻，默认每周一 `07:00`；
- `zlj.lab.maintain-overdue-remind`：逾期计划每日催办开关，默认 `true`。

### 5.2 数据范围规则

- **学生**：仅本人数据（本人预约、借用、流水）；器材/场地目录只读全量（在架且状态可约）。
- **老师**：本人数据 + 所授课程关联数据（课程名单内学生的场地使用、器材借用概览）+ 指定自己审批的学生借用单与场地背书单。
- **老师助理**：学生数据范围 + 授权老师在授权范围与有效期内的物料相关数据（申领单、领用登记、盘点任务）；有效期外或范围外数据不可见。
- **管理员**：按归口部门划分数据范围：
  - 设备处管理员：全校器材、场地、保养报废数据；
  - 学院管理员：本学院实验室及配套数据；
  - 跨归口数据只读不可操作。

### 5.3 权限隔离规则

1. 所有写操作接口在服务端校验角色 + 数据范围双重权限，前端隐藏入口仅为体验优化，不作安全依据。
2. 老师助理每次调用代领/代登记接口，服务端校验：助理身份有效（在有效期内）+ 授权范围覆盖该物料/实验室；流水同时记录操作人（助理学号）与授权人（老师工号）。
3. 管理员操作（审批、处置、配置变更）全部写入操作日志，含操作人、时间、IP、变更前后值。
4. 登录态有效期 2 小时（学生/老师视图）/8 小时（管理员视图），敏感操作（审批、报废处置）需二次输入密码确认。

## 第六章 非功能需求

### 6.1 性能需求

| 指标 | 目标值 |
| --- | --- |
| 移动端页面首屏加载 | ≤ 2s（4G 网络） |
| 管理后台列表查询（10 万级数据） | ≤ 1.5s |

| 场地预约冲突检测（含课表比对） | ≤ 800ms |

| 并发能力 | 支持 500 在线用户，预约高峰期（选课周）1000 QPS |
| 定时任务（超期扫描、审批/背书超时扫描、保养生成） | 单次执行 ≤ 5 分钟 |

### 6.2 兼容性需求

- 一套响应式 Web 应用（三端合一）：PC 优先，分辨率 ≥ 1366×768 提供完整功能，手机浏览器自适应保证核心流程可用；
- 学生视图/老师视图（移动端浏览器）：微信内置浏览器、Safari（iOS 12+）、Chrome（Android 8+）；
- 管理员视图（PC）：Chrome 90+、Edge 90+；
- 扫码能力（二期预留）：兼容微信扫一扫与浏览器调起摄像头扫码；一期借还为页面确认操作。

### 6.3 安全需求

1. 全站 HTTPS；敏感字段（手机号、密码）加密存储与传输，密码 BCrypt 哈希。
2. 接口鉴权：Token（JWT）+ 角色 + 数据范围三级校验；防 SQL 注入、XSS、CSRF。
3. 照片存储：私有桶 + 临时签名 URL（有效期 30 分钟），防止未授权访问留痕照片。
4. 越权防护：所有详情/操作接口校验数据归属（本人/数据范围），禁止通过遍历 ID 越权访问。
5. 限流：登录、短信验证码接口单 IP 每分钟 ≤ 10 次；预约提交单用户每分钟 ≤ 5 次，防恶意刷占。

### 6.4 合规需求

- 符合《个人信息保护法》：收集信息最小化（学号、姓名、手机号、人脸/指纹等生物信息不采集）；用户注销后个人信息匿名化，业务流水保留（审计要求）。
- 留痕照片仅用于责任追溯与设备管理，保存期限 3 年，到期自动清理。
- 满足学校信息系统等级保护二级要求（日志留存 ≥ 6 个月）。

### 6.5 可用性需求

- 核心流程（预约→审批→借还）步骤 ≤ 4 步；借还确认入口在学生/老师视图首页一级入口。
- 关键操作（审批驳回、报废处置、冻结资格）必须填写原因并二次确认。
- 系统故障时降级：预约列表展示缓存数据并提示"数据可能延迟"，禁止写入；消息推送失败重试 3 次后落库待人工处理。

### 6.6 埋点需求

| 埋点事件 | 关键属性 |
| --- | --- |

### 6.7 日志需求

- 业务操作日志：预约、审批、借还、处置、配置变更全量记录（操作人/时间/IP/参数/结果），保存 ≥ 3 年；
- 系统运行日志：定时任务执行明细、消息推送结果、第三方接口调用（短信/统一认证）；
- 错误日志：异常堆栈 + 请求上下文，对接告警（错误率 > 1% 时通知运维）。

## 第七章 兼容与约束

### 7.1 系统定位边界

1. 本系统定位**实验室设备管理**，覆盖器材、配件物料、场地、保养报废的全生命周期管理与**业务流转**（预约、审批、借还、盘点、处置登记）。
2. **不做设备运维**：不提供报修入口、维修工单流转、巡检任务派发、6S 评分、维修知识库、维保厂商对接等功能（V1.4 起明确移除）。设备损坏后仅在本系统变更状态、推送管理员知悉，维修执行走线下，结果由管理员回填。
3. 与后勤维修体系的关系：本系统记录的损坏状态可作为线下维修的依据参考，但不对接、不派发、不跟踪维修进度；维修完成后管理员在系统内回填结果并恢复器材状态。
4. 已移除的历史表（`tab_classroom_device`、`tab_usage_record`、`tab_work_order`、`tab_maintain_inspect`、`tab_repair_kb`）如需追溯旧数据，由 DBA 归档保留，系统不提供查询入口。

### 7.2 外部依赖

| 依赖 | 说明 | 降级方案 |
| --- | --- | --- |
| 学校统一身份认证 | 登录鉴权 | 本地账号密码兜底（管理员账号） |
| 短信通道 | 验证码、催办通知 | 应用内消息替代，短信失败自动降级 |
| 对象存储（OSS/MinIO） | 留痕照片 | 本地磁盘备份存储（仅应急） |
| 教务课表数据源 | 场地冲突检测 | 支持手工导入 Excel 课表 |
| 飞书（二期） | 组织同步、多维表格台账、消息 | 本期通过接口抽象层预留，不依赖 |

### 7.3 数据约束

- 单实验室器材容量上限 5000 件；单用户同时在借器材 ≤ 10 件（可配置）；
- 照片单张 ≤ 5MB，单次上传 ≤ 9 张；文件存储总量预警线 80%；
- 定时任务窗口避开业务高峰（00:00–07:00 执行批量任务）。

### 7.4 技术约束

- **前后端不分离**：采用后端模板渲染（服务端直出页面），不单独建设前端 SPA 工程与独立 API 层；
- **三端合一**：一套 Web 应用按登录角色呈现学生视图/老师视图/管理员视图，响应式布局 PC 优先、手机浏览器自适应；
- 不开发独立 H5 站点与原生 App。

## 第八章 上线方案

### 8.1 试点范围

- 一期试点：**1–2 个学院、3–5 间实验室**（建议选设备量大、管理员配合度高的学院，如信息学院/工程学院）；
- 试点用户：试点学院全体老师、学生及设备处管理员；
- 试点周期：4–6 周，期间并行旧台账（Excel）双轨核对。

### 8.2 上线步骤

1. **第 1 周**：基础数据初始化（实验室、器材、配件物料、用户导入），管理员培训（2 场）；
2. **第 2 周**：开放器材预约与借还，冻结旧 Excel 借用登记；
3. **第 3 周**：开放场地预约、物料申领与助理授权；
4. **第 4 周**：开放保养计划与报废流程；关闭双轨，正式单轨运行；
5. **第 5–6 周**：问题修复与体验优化，输出试点复盘报告，决策全校推广。

### 8.3 数据迁移

- 器材台账：旧 Excel 清洗后批量导入（含资产编号、名称、价值分级、存放位置、当前状态），导入后管理员抽样核对 ≥ 10%；
- 在借器材：以导入日为准，管理员手工登记为"在借"并通知使用人确认；
- 物料库存：实盘一次后录入，作为期初库存；
- 用户与课表：统一认证/教务系统同步，不支持手工迁移。

### 8.4 推广计划（试点后）

- 第二批：其余理工科学院（设备密集），预计 8 周；
- 第三批：全校推广（含文科实验室、公共机房），预计 4 周；
- 每批推广前输出配置清单（实验室/器材/管理员账号），沿用试点培训材料。

## 附录 A 典型场景

### 场景 1：学生借用贵重示波器（完整链路）

1. 学生 A 在学生视图查询"示波器"，选择实验室 L301 的某台（VALUABLE），提交预约（明天 14:00–17:00），确认审批老师（默认任课老师，可改选）→ 单据状态 `PENDING_TEACHER`；
2. 系统校验：时段在 7 天 4 时段限额内、无冲突（待审不占时段）；老师 4 小时未审系统自动催办，24 小时未审推送管理员可代批；
3. 老师 T 审批通过 → 因器材贵重，单据转 `PENDING_ADMIN` 进入管理员 B 待办；
4. 管理员 B 次日 09:00 审批通过（耗时 2.5h，系统已催办 1 次）→ `APPROVED`，通过瞬间系统复查时段冲突 → 学生 A 收到通过通知；
5. 学生 A 按时到实验室，在借用单上确认借出，强制拍摄外观照 2 张上传 → 器材状态 IN_USE；
6. 17:00 前学生在借用单上确认归还，拍外观照，选择"外观完好"→ 器材恢复 IDLE，流程闭环。

### 场景 2：归还发现损坏（只改状态不派单）

1. 学生 A 归还万用表时选择"有损坏"，拍摄损坏部位照片并填写说明"表笔接口断裂"；
2. 系统：归还记录标记 DAMAGED、器材状态 → MAINTAINING、推送管理员 B 知悉消息；
3. 管理员 B 线下联系维修商送修；5 天后修好，在后台「损坏异常处理」回填维修结果（维修商/费用/结果说明），器材状态恢复 IDLE；
4. 若无法修复，管理员 B 在器材台账直接发起报废申请，进入报废四态流转。

### 场景 3：老师预约实验室上课 + 助理代领物料

1. 老师 C 预约实验室 L205 周三 10:00–12:00（系统与课表比对无冲突），审批通过；
2. 老师 C 提前授权学生 D 为助理（范围：L205 耗材；有效期：本学期）；
3. 上课当天场地单到点自动 IN_USE → 学生 D 凭助理身份到库房代领焊锡丝 2 卷，流水记录"经办：学生 D / 授权：老师 C"；
4. 12:00 过后系统自动 FINISHED，场地使用档案归档；课后老师 C 在保养模块手动登记日常保养记录。

## 附录 B 主要状态机速览

### B.1 器材预约单

**学生单**：`PENDING_TEACHER` →（老师审批通过，普通器材）→ `APPROVED`
`PENDING_TEACHER` →（老师审批通过，贵重器材）→ `PENDING_ADMIN` →（管理员审批通过）→ `APPROVED`
**老师单**：普通器材提交即 `APPROVED`；贵重器材直接 `PENDING_ADMIN` →（管理员审批通过）→ `APPROVED`
`APPROVED` →（确认借出）→ `CHECKED_OUT` →（归还）→ `RETURNED`
`PENDING_TEACHER` / `PENDING_ADMIN` →（驳回/用户取消）→ `REJECTED` / `CANCELLED`

### B.2 器材

`IDLE` ↔（预约生效/借出）`RESERVED` / `IN_USE`
`IN_USE` →（归还损坏）→ `MAINTAINING` →（管理员回填修复）→ `IDLE`
`MAINTAINING` / `IDLE` →（报废流程）→ `SCRAPPED`

### B.3 场地预约单

**学生单**：`PENDING_ENDORSE` →（老师背书通过）→ `PENDING` →（管理员审批通过）→ `APPROVED`
`PENDING_ENDORSE` →（背书拒绝）→ `REJECTED`；（48h 背书超时）→ `CANCELLED`
**老师单**：提交即 `PENDING`（无背书环节）
`APPROVED` →（到 start_time 自动）→ `IN_USE` →（到 end_time+2h 自动 / 管理员强制结束）→ `FINISHED`
`APPROVED` →（开始前用户取消）→ `CANCELLED(MANUAL)`
`APPROVED` →（管理员仲裁/停用）→ `CANCELLED(FORCE)`
`PENDING` →（start_time 已过未审批）→ `CANCELLED(AUTO_EXPIRED)`

### B.4 报废单

`PENDING` →（提交鉴定）→ `APPRAISING` →（鉴定通过+审批）→ `APPROVED` →（处置销账）→ `DISPOSED`
`APPRAISING` / 审批环节 →（不通过）→ `REJECTED`
