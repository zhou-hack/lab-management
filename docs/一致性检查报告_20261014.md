# 数据库与后端代码一致性检查报告

**日期**：2026-10-14
**范围**：物料管理模块 13 张表（`sql/lab_management_all.sql` 定义）
**比对基准**：以 MySQL 实际运行库 `lab_management` 为准

## 一、检查方法

1. 从 4 个 SQL 文件（`sys_rbac.sql`、`sys_policy.sql`、`assistant_grant.sql`、`lab_management_all.sql`）提取 37 张表的结构定义
2. 从 `src/main/java/com/labmanage/module/item/entity/` 提取 13 个实体类的 `@TableName`、字段名、Java 类型
3. 从 MySQL `information_schema.COLUMNS` 查询实际运行库的列名、类型、可空性、默认值
4. 三方逐表逐字段比对

## 二、比对结果汇总

| 比对维度 | 实际库 vs Java 代码 | SQL 文件 vs 实际库 |
| --- | --- | --- |
| 表名（13 张） | 全部一致 | 全部一致 |
| 字段名 | 全部一致 | **2 处冲突** |
| 数据类型 | 全部一致 | 全部一致 |
| 约束条件 | 全部一致 | 冲突已随字段名修复 |

## 三、发现的冲突

### 冲突 1：`stock_document_line` 表字段名 `qty` → `quantity`

| 项 | SQL 文件（修复前） | 实际数据库 | Java 实体 |
| --- | --- | --- | --- |
| 字段名 | `qty` | `quantity` | `quantity` |
| 数据类型 | `DECIMAL(18,3) NOT NULL` | `decimal NO` | `BigDecimal` |
| CHECK 约束 | `CHECK (qty > 0)` | 实际库为 `quantity > 0` | — |

**影响范围**：
- `sql/lab_management_all.sql` 第 698 行注释、第 707 行列定义、第 727 行 CHECK 约束
- Mapper 层自定义 SQL：`StockDocumentLineMapper` INSERT 使用列名 `quantity`（与实际库一致，无需改）
- Java 实体 `StockDocumentLine.quantity`（与实际库一致，无需改）

**修复内容**：将 SQL 文件中 3 处 `qty` 改为 `quantity`，使其与实际数据库一致
