## 1 项目概述

### 1.1 模块定位

| 维度 | 说明 |
| --- | --- |
| 业务定位 | 场地模块是"高校智联教师实验室系统"的空间主档，以单表承载教室/实训室台账（名称、类型、位置、容量、配套设备、开放时段、状态），为预约、课表、资产、物料、保养报废提供唯一空间 ID 与名称快照来源 |
| 上游依赖 | 依赖 [sys_rbac.sql](../sql/sys_rbac.sql) 已建 RBAC（`sys_user`、`sys_role`、`sys_permission`、`sys_menu`、`sys_user_data_scope`），复用 `common` 公共地基（`BaseEntity`、`Result`、`PageResult`、`BusinessException`、`PageUtils`、`Instant` 序列化器）与 `config`（`MybatisPlusConfig`、`MyMetaObjectHandler`、`JacksonConfig`） |
| 下游被依赖 | ① 预约模块：`lab_booking.lab_id`、`lab_slot.lab_id`；② 课表模块：`course_schedule.lab_id`、`schedule_occurrence` 经 `lab_slot` 占用；③ 资产模块：`equipment_asset.lab_id`、`stock_location.lab_id`、`workstation.lab_id`；④ 数据范围：`sys_user_data_scope.lab_id`（LAB 级范围，目标为 biz_space.id）；⑤ 助理授权：`assistant_grant_scope.lab_id`。以上 `lab_id` 语义统一为 `biz_space.id`（见数据库设计 v1.1 修订说明） |
| 数据交互方式 | 单表自持，无模块内外键；`sys_user_data_scope.lab_id` 外键由本模块脚本补充（RESTRICT）。审计字段 `create_user_id / update_user_id` 不建外键 |

### 1.2 主要功能

| 子功能点 | 说明 |
| --- | --- |
| 场地新增 | 管理员录入名称、类型、位置、容量、配套设备、开放时段；状态缺省 AVAILABLE；名称全局唯一（含已删除记录，删除后不复用） |
| 场地编辑 | 管理员全量编辑；开放时段与状态为空表示保留原值；位置/设备清单为空即清空 |
| 启用/停用 | 启用 → AVAILABLE；停用/关闭 → CLOSED；维护中 MAINTAINING 经编辑接口设置；停用后禁止新建预约，已有预约由预约模块按策略处理 |
| 场地删除 | 逻辑删除；删除前做业务引用检查（LAB 级数据范围授权；预约/资产引用检查待对应模块落地后追加） |
| 场地查询 | 所有人（登录后）分页查询：名称/位置模糊、类型、状态、容量区间；排序白名单；下拉 options 供下游联调 |
| 场地详情 | 单条详情含全部台账字段与审计时间 |
| 场地可用性校验 | 由预约模块实现（所选时间窗与 `lab_slot` 占用比对，且场地状态须为 AVAILABLE）；本模块提供 `options?availableOnly=true` 支撑 |
| 场地图片上传 | **一期不做**（不建图片表，不提供上传接口） |

### 1.3 开发目标

| 类别 | 指标 |
| --- | --- |
| 业务目标 | ① 完成场地台账全部 CRUD 与启停；② 提供列表/详情/options 接口，供前端管理端和后续预约模块联调；③ 登记场地模块权限标识与菜单初始数据，对接动态路由白名单 |
| 技术指标 | ① 接口统一 `/api/v1/space/spaces` 前缀、RESTful、返回 `Result/PageResult`、成功 `code=0`；② 分页默认 `pageNum=1/pageSize=20`，上限 100；③ 主键雪花 ID 接口序列化为字符串；④ 时间点 `Instant` UTC 三位毫秒输出，`open_start/open_end` 为上海本地 `HH:mm` 无时区换算；⑤ 实体继承 `BaseEntity`，加 `@TableName("biz_space")`，逻辑删除由 `@TableLogic`；⑥ 权限标识 `space:space:操作`，受保护接口加 `@SaCheckPermission`；⑦ 控制器不暴露实体/ORM 分页对象，统一 DTO/VO 契约 |
| 一期边界 | 不实现场地预约审批、课表占用、签到/门禁、场地图片表；数据范围行级过滤暂不启用（单表无组织锚点列，见 4.3） |

## 2 功能需求规格说明

### 2.1 字段定义（biz_space）

类型记号沿用 [docs/数据库设计.md](数据库设计.md) 2.1：

| 字段（DB 列名） | Java 属性 | 类型记号 | MySQL | 必填 | 约束与含义 |
| --- | --- | --- | --- | --- | --- |
| `id` | id | ID | BIGINT | 系统生成 | 雪花 ID（ASSIGN_ID），接口输出字符串 |
| `space_name` | spaceName | NAME | VARCHAR(128) | 是 | 场地名称，全局唯一；逻辑删除后不复用（删除行仍占用唯一索引） |
| `space_type` | spaceType | SHORT | VARCHAR(32) | 是 | Java 枚举 `SpaceType`：CLASSROOM 教室 / TRAINING_ROOM 实训室；CHECK 双保险 |
| `location` | location | NAME | VARCHAR(128) | 否 | 位置自由文本，如"A 楼七层 A703" |
| `capacity` | capacity | INT | INT | 是 | 容纳人数，`> 0`（CHECK + 服务端校验） |
| `facilities` | facilities | TXT | TEXT | 否 | 配套设备清单（自由文本） |
| `open_start` | openStart | CLOCK | TIME(0) | 是 | 每日开放开始，上海本地时间；DB 默认 `08:00`；接口 `HH:mm` 字符串 |
| `open_end` | openEnd | CLOCK | TIME(0) | 是 | 每日开放结束，上海本地时间；DB 默认 `21:00`；`open_start < open_end`（CHECK + 服务端校验） |
| `status` | status | SHORT | VARCHAR(32) | 是 | Java 枚举 `SpaceStatus`：AVAILABLE 可用 / MAINTAINING 维护中 / CLOSED 关闭；落库，默认 AVAILABLE |
| `create_time` / `update_time` | — | TIME | DATETIME(3) | 系统 | UTC，默认 `UTC_TIMESTAMP(3)`，`update_time` ON UPDATE |
| `deleted` | — | BOOL | TINYINT | 系统 | 逻辑删除 0/1（`@TableLogic`） |
| `create_user_id` / `update_user_id` | — | ID | BIGINT | 系统 | 审计操作者，服务端 `SecurityUtils.currentUserId()` 填充，不建外键 |

### 2.2 行为规则

1. **名称唯一**：创建与编辑均按"含逻辑删除记录"前置校验，命中即返回 40900"场地名称已存在（含已删除记录，名称不可复用）"，避免唯一索引冲突落入 500。
2. **开放时段**：入参 `HH:mm` 格式（`@Pattern` 校验）；创建空值取默认 08:00/21:00，编辑空值保留原值；`open_start >= open_end` 返回 40000。
3. **状态流转**：`AVAILABLE ⇄ CLOSED`（enable/disable 及编辑接口）、`AVAILABLE/MAINTAINING/CLOSED` 互转（编辑接口）；状态落库取代 v1.0"派生不入库"决议。派生占用（某时段是否被预约占用）由预约模块按时间窗判断，不属于本字段。
4. **停用语义**：CLOSED 后禁止新建预约/排课占用；已有生效预约不自动取消（由预约模块按策略处理）。
5. **删除语义**：逻辑删除；删除前检查 `sys_user_data_scope.lab_id` 有效 LAB 级授权，存在则 40900"存在未结业务引用"；预约/资产模块落地后在此追加引用检查。删除后名称不可复用。
6. **审计**：创建/编辑/启停/删除均写 `update_user_id`；`create_user_id` 仅创建时写入；时间由 MyMetaObjectHandler / DB UTC 默认值填充，客户端不可覆盖。

### 2.3 用户操作权限区分

| 操作 | 普通用户（教师/学生） | 管理员 |
| --- | --- | --- |
| 分页查询 / options / 详情 | 允许（`space:space:list` / `space:space:read`） | 允许 |
| 新增 / 编辑 / 启用 / 停用 / 删除 | 禁止（无权限标识，接口 40300） | 允许（`space:space:create/update/delete`） |

一期不开发老师授权学生代理审批功能（代理审批属预约模块，且须经助理授权体系）。

## 3 数据结构与接口设计

### 3.1 建表脚本

[sql/biz_space.sql](../sql/biz_space.sql)（执行前提：先执行 [sql/sys_rbac.sql](../sql/sys_rbac.sql)）：

- **DDL**：`biz_space` 单表；`uk_biz_space_name` 唯一索引；`idx_biz_space_type/idx_biz_space_status` 查询索引；CHECK 约束（type/status/capacity/open 窗口/deleted）。
- **跨模块外键**：`sys_user_data_scope.lab_id → biz_space.id`（RESTRICT）；`campus_id/building_id` 列按 RBAC 定稿保留，单表模式下无挂靠表，不加外键。
- **种子数据**：3 条示例场地（A703 网络实训室 / C703 电子电工实训室 / 教学楼201多媒体教室）；权限 101-105；菜单 1001-1005（1002 沿用前端白名单路由 `/admin/space/labs` → `admin/space/LabList`）；ADMIN 全量权限与菜单、TEACHER/STUDENT 只读权限；管理员 ALL+WRITE 数据范围（id=1）。

### 3.2 接口契约（前缀 `/api/v1/space/spaces`，`SpaceController`）

| 方法与路径 | 权限 | 入参 | 出参 | 说明 |
| --- | --- | --- | --- | --- |
| `GET /` | `space:space:list` | `SpacePageQuery`（query） | `Result<PageResult<SpaceListVO>>` | 分页；名称/位置模糊、类型、状态、容量区间；排序白名单 `spaceName/capacity/createTime/updateTime` |
| `GET /options` | `space:space:list` | `spaceType?`、`minCapacity?`、`availableOnly?`（query） | `Result<List<SpaceOptionVO>>` | 下拉选项；`availableOnly=true` 仅 AVAILABLE |
| `GET /stats` | `space:space:list` | 无 | `Result<SpaceStatsVO>` | 统计卡片：total/available/maintaining/closed 四计数（按 status 分组聚合，未知状态仅计总数） |
| `GET /{id}` | `space:space:read` | 路径 id | `Result<SpaceDetailVO>` | 详情 |
| `POST /` | `space:space:create` | `SpaceCreateDTO`（body） | `Result<SpaceDetailVO>` | 新增；状态缺省 AVAILABLE，时段缺省 08:00-21:00 |
| `PUT /{id}` | `space:space:update` | `SpaceUpdateDTO`（body） | `Result<SpaceDetailVO>` | 编辑；时段/状态空值保留原值 |
| `POST /{id}/enable` | `space:space:update` | 路径 id | `Result<Void>` | 状态 → AVAILABLE |
| `POST /{id}/disable` | `space:space:update` | 路径 id | `Result<Void>` | 状态 → CLOSED |
| `DELETE /{id}` | `space:space:delete` | 路径 id | `Result<Void>` | 逻辑删除（引用检查） |

通用契约：JSON 返回体 `code/msg/data`，成功 `code=0`，失败 `data=null`；分页响应含 `records/total/pageNum/pageSize`；id 以字符串承载；`createTime/updateTime` UTC 三位毫秒（如 `2026-10-13T01:00:00.000Z`）；`openStart/openEnd` 为 `HH:mm`；枚举以 code 字符串序列化（非法值由校验层转 40000）。

### 3.3 代码结构（`com.labmanage.module.space`）

```
module/space/
├── enums/       SpaceType（CLASSROOM/TRAINING_ROOM）、SpaceStatus（AVAILABLE/MAINTAINING/CLOSED）
├── entity/      BizSpace（@TableName("biz_space")，继承 BaseEntity）
├── mapper/      BizSpaceMapper（BaseMapper + 名称含删除查重 + LAB 范围引用计数）
├── dto/         SpaceCreateDTO、SpaceUpdateDTO（record + Jakarta Validation）、SpacePageQuery（BasePageQuery）
├── vo/          SpaceListVO、SpaceDetailVO、SpaceOptionVO（record，id 字符串化）
├── service/     SpaceService + impl/SpaceServiceImpl（业务规则、排序白名单、审计填充）
└── controller/  SpaceController（@SaCheckPermission + Result/PageResult）
```

### 3.4 公共层配套修订

- [GlobalExceptionHandler](../src/main/java/com/labmanage/common/exception/GlobalExceptionHandler.java)：`BusinessException` 的 HTTP 状态按错误码映射（40000→400、40100→401、40300→403、40400→404、50000→500，其余→409），保证"HTTP 状态反映真实结果"（此前一律 409，参数错误会错落 409）。
- 枚举持久化模式：`@EnumValue` 标注 code + `@JsonValue` 于 `getCode()` + `@JsonCreator fromCode()`（非法值返回 null 由校验层拦截），与全仓枚举约定一致。

## 4 关键设计决策

### 4.1 单表与开放时段

单表后无楼栋/校区层级，位置为自由文本；开放规则由"同日多段+有效期"简化为**每日单时段**（08:00-21:00 默认）。学期/假期差异、多段开放等复杂规则待预约模块（分组 B）有真实需求时再评估扩展（如引入独立时段表或字段），一期不预留。

### 4.2 状态落库与派生占用

`status`（AVAILABLE/MAINTAINING/CLOSED）直接落库，管理员可维护；"某时段是否被占用"为派生值，由预约模块基于 `lab_slot` 时间窗计算。二者分离，避免把实时占用写回主档造成并发失真。

### 4.3 数据范围（sys_user_data_scope）

单表无 department/campus/building 锚点列，一期**不做行级数据范围过滤**，访问控制由 `@SaCheckPermission` 权限标识完成（管理员全量、师生只读）。LAB 级范围仍以 `biz_space.id` 为目标（外键 RESTRICT + 删除前引用检查）；CAMPUS/BUILDING 范围类型为 RBAC 保留类型，暂无挂靠表。后续若引入组织锚点需补充列并重新启用行级过滤。

## 附记·决议修订登记（v1.0 → v2.0）

| 决议 | v1.0 结论 | v2.0 处置 |
| --- | --- | --- |
| Q1 场地类型字典 | 4 类 + OTHER（COMPUTER_ROOM/MULTIMEDIA_ROOM/ELECTRONIC_LAB/TRAINING_ROOM/OTHER） | **作废**，收敛为两值 CLASSROOM/TRAINING_ROOM（业务确认）；如需扩展在枚举与 CHECK 同步登记 |
| Q2 状态是否落库 | 派生不入库（实体仅 enabled） | **作废**，status 落库三值 AVAILABLE/MAINTAINING/CLOSED；派生占用归预约模块 |
| Q3 跨楼栋调整 | 停用+新建（building_id 不可改） | **作废**，单表无楼栋概念，位置 location 自由文本可编辑 |
