# 对接扩展点建议清单（教务系统 · 物料资产系统）

> 日期：2026-10-26 ｜ 基准：dev/space 最新代码与三张流程图（v2.1）
> 用途：后续对接**教务系统**（拉取补课类预约数据）与**物料资产系统**（按教室绑定管理员、设备归属教室）时，在现有流程节点上的预留能力盘点与适配边界

## 一、教务系统对接（补课类预约数据拉取）

| 编号 | 扩展点位置（图节点 / 代码点） | 现状与预留能力 | 对接适配方向 |
| --- | --- | --- | --- |
| E1 | **单据类型扩展**（图二"提交预约申请"建档；`BookingFlowService.onSubmit`，`biz_document.document_type`/`document_no`） | document_type 现仅 `LAB_BOOKING`/`LAB_BOOKING_SERIES`，document_no 前缀机制（LAB/LBS）已通用 | 新增类型如 `LAB_BOOKING_MAKEUP`（前缀 LAM）即可让补课单走同一审批链、同一时间线、同一导出，无需改流程骨架 |
| E2 | **外部幂等键**（提交建档；`biz_document.idempotency_key`、`lab_booking_series.idempotency_key`） | 幂等键机制已具备（周期预约已用客户端幂等键防重） | 教务推送直接用教务单号作幂等键，重复推送/网络重试天然防重 |
| E3 | **审批阶段编排**（图二"管理员核对 ADMIN_REVIEW"；`approval_task.stage_code/required_role/timeout_action`） | 现为单阶段 ADMIN_REVIEW；stage/角色/超时动作均为数据列，可加阶段或改角色 | 补课单若免审批：建档时直接落 APPROVED 任务（复用 `onGeneratedApproved` 模式）；若需教务处长审批：新增 stage 即可 |
| E4 | **来源标记缺口**（lab_booking 表） | ⚠️ 现无 source_type/source_id 字段，补课单与教师自发单无法区分 | 需加列（`source_type`/`source_id`）或扩展表；占用总览、预约情况、CSV 导出按来源过滤均依赖此字段 |
| E5 | **节次映射**（图二"场地·日期·节次"；`class_period` 12 节次） | 节次为本校作息（period_no 1-12，上海本地 CLOCK） | 教务推送的时间片需经"教务节次编码 → 本校 period_id"映射表换算；或直接提交 UTC 时间点走现有校验链 |
| E6 | **冲突判定复用**（图二"校验与冲突检查"、批准行锁复查；`BookingServiceImpl.create/approve`） | 时段冲突 40900 语义完善，提交与批准双检查 | 教务批量导入应**走服务层 create/approve 链路**复用冲突与行锁，禁止直写表；补课占用与预约占用天然互斥 |
| E7 | **课表占用并入总览**（图二"场地占用总览"；`occupancy`/`LabOccupancyVO.slots`） | 总览目前只看 lab_slot 预约槽；课表占用为 PRD 二期已登记缺口 | 教务课表占用建议以"虚拟 slot（来源类型=COURSE）"并入同一返回结构，前端四态派生无需改动 |

## 二、物料资产系统对接（按教室绑定管理员 · 设备归属教室）

| 编号 | 扩展点位置（图节点 / 代码点） | 现状与预留能力 | 对接适配方向 |
| --- | --- | --- | --- |
| M1 | **场地主档引用点**（图一"下游模块引用 lab.id"虚线框；lab 表主键） | lab.id 已被预约（lab_booking/lab_slot）、助理授权、数据范围引用；删除场地有"被引用→40900"拦截模式 | 设备归属教室直接外键 `lab_id`；场地删除引用检查需同步登记设备表（复用现有拦截模式） |
| M2 | **按教室绑定管理员**（RBAC 数据范围；`sys_user_data_scope`） | 已有 scopeType=ALL/DEPARTMENT/CAMPUS/BUILDING/**LAB** + READ/WRITE 五级数据范围 | 物料管理员对教室的管辖可直接落 user_data_scope(LAB)；若需"负责人"单值语义再建轻量 lab_manager 表 |
| M3 | **助理授权复用**（`assistant_grant`） | scopeType=LAB、action=**ISSUE/RETURN** 已按物料领还语义定义并交付 | 学生领用/归还物料的授权判定直接复用 assistant_grant 有效期机制，无需新建授权体系 |
| M4 | **设备随场地状态联动**（图一启停分支；lab.status） | 场地三态 AVAILABLE/MAINTAINING/CLOSED 落库 | 设备可借性 = 设备自身状态 AND 所属场地状态（停用场地的设备默认不可借）；该联动在设备模块实现，场地侧零改动 |
| M5 | **开门事件联动**（图二签到/清点节点；document_event 事件流） | CHECKIN/CHECKOUT 事件不可变留痕、可按 document 查询 | "开门后允许领用物料"可由物料系统查询事件流实现；一期无消息总线，对接方式为接口查询/数据库视图，二期可换订阅 |
| M6 | **台账数据供给**（图一只读框；list/options/stats/export 接口与服务层） | 分页/选项/统计/CSV 导出全部具备 | 物料系统同库部署可直接调 SpaceService 服务层；跨系统部署走 `/api/v1/space/labs/options` 等只读接口 + token |

## 三、对接通用原则（两系统共用）

1. **不动场地侧骨架**：以上扩展点均按"新增类型/新增引用/服务层复用"设计，对接不需要修改现有预约与台账主流程。
2. **写操作一律走服务层**：任何外部系统产生占用都必须经过冲突校验与行锁路径，禁止直写 lab_booking/lab_slot。
3. **时间口径入站即归一**：外部时间点必须带偏移量（ISO 8601），入站转 UTC；节次类数据先映射本校 class_period。
4. **幂等先行**：所有外部推送以对方单号为幂等键，重推不产生重复单据。
5. **删除保护联动**：新下游表引用 lab.id 后，须同步登记场地删除/停用的引用检查，保持台账图的拦截承诺成立。
