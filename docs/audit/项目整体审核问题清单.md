## 二、问题明细

### B1（高）前端雪花 ID 转 Number，精度丢失致授权错乱

- 位置：`frontend/src/views/grant/GrantManage.vue:342,347`
- 证据：`studentId: Number(form.studentId)`、`labId: Number(labId)`（源码复核 2026-10-26 仍在）
- 分析：后端 VO 已显式用 String 承载 19 位雪花 ID，前端却转 Number。雪花 ID ≈10^18 超过 `Number.MAX_SAFE_INTEGER`（≈9×10^15），低 3~4 位被舍入。后果：创建助理授权大概率报"学生不存在"；理论上可能恰好命中另一 ID，造成**给错误对象授权**的安全风险。全项目仅此处对实体 ID 做 Number 转换。
- 影响范围：助理授权模块（roles），GrantManage 创建链路。
- 修复：`studentId: form.studentId`、`labId: labId` 字符串透传（后端 DTO 为 Long，Jackson 可直接解析字符串数字）。
- **修复记录（2026-10-26，真实落地）**：已按上述方案移除两处 `Number()` 转换，字符串透传；前端 ESLint 0 错误（修复后 GrantManage.vue 无告警）。

## 七、三张流程图整体思路与跨图一致性核对

### 7.1 整体流程思路（三张图的分层关系）

三张图构成"资源 → 状态 → 流程"三层视图，逻辑上自底向上支撑：

```text
图二 场地台账管理（资源层，/api/v1/space/spaces）
  管理员：新增/导入/编辑/启停/删除 → 写入 lab 表（空间主档）
  师生：只读查询/下拉/统计/导出（经 space:space:list/read 授权）
  出口：lab.id 作为下游外键锚点（lab_booking / lab_slot / 数据范围 / 助理授权）

图三 lab_booking 状态机 + lab_slot 生命周期（状态层）
  落库四态：PENDING →(批准，写 lab_slot)→ APPROVED →(撤销/超时)→ CANCELLED
            PENDING →(驳回)→ REJECTED
  派生阶段（不落库）：UPCOMING / IN_USE / FINISHED（事件+时间驱动）
  占用槽：创建(批准时) → 占用中(released_at 空) → 释放(released_at 写入)

图一 预约业务流程（流程层，角色泳道）
  申请（校验+冲突检查）→ 审批（核对/驳回/超时取消）→ 使用（签到→清点）→ 归档
```

### 7.2 单图核对结论

- **图二（台账）**：与源码逐节点一致（第 3 轮已核），B21 措辞口径已在图档 v2.1 采纳修正。
