# 场地管理系统检查报告

检查日期：2026-10-16
检查范围：后端全量源码、前端全量源码、配置文件、SQL 脚本、项目文档

## 环境问题（阻塞性）

### 1. Java 版本不匹配
- 系统安装 Java 1.8.0_101，项目要求 JDK 17（Eclipse Temurin 17.0.20.1+1）
- 后端无法编译运行，`./mvnw.cmd verify` 将失败
- 需安装 JDK 17 并将 `JAVA_HOME` 指向 JDK 17 根目录

### 2. Node.js/npm 未安装
- `node` 和 `npm` 不在系统 PATH 中，项目要求 Node.js 24.21.0 LTS / npm 12.2.0
- 前端无法执行 `npm ci`、`npm run lint`、`npm run test`、`npm run build`
- 需安装 Node.js 24.21.0 并升级 npm 至 12.2.0

## 后端问题

### 中等风险

#### 3. `SpaceServiceImpl.stats()` 未防护 `SpaceType.valueOf()` 异常
- 文件：`module/space/service/impl/SpaceServiceImpl.java` 第 151 行
- 如果 `lab_type` 字段为 NULL 或包含无效枚举名，`SpaceType.valueOf(type)` 会抛 `IllegalArgumentException`
- 该异常会被全局异常处理器捕获为 500，但应使用安全解析，参考同方法中 status 的 `switch-default-warn` 模式
- 建议：用 try-catch 包裹或先校验枚举有效性

#### 4. CORS 未暴露 `Content-Disposition` 响应头
- 文件：`config/CorsConfig.java`
- CSV 导出接口设置了 `Content-Disposition: attachment; filename=...` 响应头
- CORS 配置的 `allowedHeaders` 仅含 `Authorization`、`Content-Type`，未配置 `exposedHeaders`
- 跨域环境下浏览器无法读取文件名，建议添加 `.exposedHeaders("Content-Disposition")`

#### 5. `application-dev.yml` 和 `application-test.yml` 包含无效 JPA 配置
- 两个配置文件均含 `spring.jpa.open-in-view: false`
- 本项目使用 MyBatis-Plus，不使用 JPA，该属性无意义
- 建议移除以避免误导

#### 6. `PolicyServiceImpl` 缓存无自动刷新机制
- 文件：`roles/service/impl/PolicyServiceImpl.java`
- 策略缓存为进程内懒加载，仅在显式调用 `refresh()` 时刷新
- 数据库中策略参数变更后不会生效，需重启或手动触发
- 建议：增加定时刷新或数据库变更通知机制

#### 7. `SmsCodeServiceImpl.verify()` 存在竞态条件
- 文件：`roles/service/impl/SmsCodeServiceImpl.java` 第 75-81 行
- 验证码验证失败的 get-check-put 序列非原子操作
- `codes.remove(phone, entry)` 是原子的，但后续 `codes.put(phone, new CodeEntry(...))` 可能与并发请求竞争
- 影响：并发错误验证时 failCount 可能不准确，但不会导致安全性问题（正确码已通过 remove 移除）
- 建议：使用 `compute` 方法替代 get-put 序列

### 低风险

#### 8. `BookingServiceImpl` 中 `requireBooking()` 重复调用
- 文件：`module/booking/service/impl/BookingServiceImpl.java`
- `detail()` 方法先调用 `requireBooking(id)` 获取 booking 做权限校验，随后 `detailEntity(id, ...)` 再次调用 `requireBooking(id)`
- `create()` 方法插入后调用 `detailEntity(booking.getId(), ...)` 也重新查询
- 影响：同一请求多一次 DB 查询，建议将已查到的实体传递下去

#### 9. CORS 未允许 `PATCH` 方法
- 文件：`config/CorsConfig.java`
- 开发文档约定 PATCH 用于部分更新，但 CORS 仅允许 `GET/POST/PUT/DELETE/OPTIONS`
- 当前无 PATCH 端点，但后续模块可能需要，建议提前添加

#### 10. `BookingCreateDTO` 使用 `Instant` 而非 `OffsetDateTime`
- 文件：`module/booking/dto/BookingCreateDTO.java`
- 开发文档约定"入参使用 `OffsetDateTime` 后转 `Instant`"
- 实际通过自定义 `InstantDeserializer` 直接将 ISO 8601 偏移量解析为 `Instant`，功能等价
- 属于约定偏差，不影响运行，建议与文档对齐或在文档中补充说明

## 前端问题

### 低风险

#### 11. `frontend/src/components/` 目录缺失
- 开发文档 `docs/development.md` 目录约定中包含 `src/components`（公共组件）
- 实际项目中未创建该目录
- 当前公共组件直接内联于各页面，后续抽取复用组件时需创建

#### 12. 登录页 `submit()` 缺少错误处理
- 文件：`frontend/src/views/login/LoginView.vue`
- `store.login()` 调用在 try-finally 中，但 catch 分支缺失
- 请求拦截器已统一弹窗提示，但 `loading.value = false` 后无额外处理
- 功能上可用，但未处理登录失败后的状态重置（如表单清空或焦点回归）

## 架构观察（非缺陷）

### 预约状态无自动流转
- `BookingStatus` 无 `IN_USE`/`FINISHED` 落库状态，通过 `runtimePhase()` 运行时派生
- 已结束的 APPROVED 预约不会自动变更状态，统计中仍计入 APPROVED
- 当前为有意设计（代码注释已说明），后续如需自动结清需增加定时任务

### 短信验证码为内存存储
- `SmsCodeServiceImpl` 使用 `ConcurrentHashMap` 存储验证码，重启即失效
- 仅适用于单实例部署，代码注释已标注
- 多实例部署时需迁移至 Redis 等共享存储

### 无 `@MapperScan` 注解
- 各 Mapper 使用 `@Mapper` 注解逐个声明，未在启动类或配置类使用 `@MapperScan`
- 当前可正常工作，但新增 Mapper 时需记得添加注解

## 文档一致性

- `docs/development.md` 与 `AGENTS.md` 技术栈、命名约定、时间规范一致
- SQL 脚本（`sql/sys_rbac.sql`、`sql/lab_management_all.sql` 等）与实体定义对应
- 权限标识（`space:space:*`、`booking:lab:*`）前后端一致
- 前端 API 封装与后端 Controller 路径完全对应
