# 数据库改动记录

记录本仓库每次数据库结构（DDL）与种子数据（DML）的改动，供组员同步本地库与审查使用。

## 使用规则

- 每次改动数据库后，在下方"改动明细"**倒序追加**一条（最新在最上）。
- 每条必须写清：日期、类型（结构/种子/迁移/修复）、涉及文件、改动说明、对旧库影响。
- 结构改动必须同步更新 `docs/数据库设计.md` 与 `sql/` 对应脚本，三者保持一致。
- 全新建库按序执行：`sys_rbac.sql` → `sys_policy.sql` → `assistant_grant.sql` → `lab_management_all.sql` → `sys_operation_log.sql` → `sys_scope.sql` → `sys_ops_role.sql` → `docx_seed_import.sql`。
- 旧库升级不重建，执行 `sql/migrations/` 下对应迁移脚本（幂等，可重复执行）。
- 编号段占用见文末速查表，新增种子数据先登记再使用。

### 2026-10-19 · 修复 · 菜单 205 顺序错误 + 数据范围种子去重

- 涉及文件：`sql/lab_management_all.sql`
- 改动说明：
  1. 菜单 205 `ITEM_ASSISTANT_PICKUP`（物料代领）引用权限 122（`item:request:list`），此前误插在 4.9 节第一阶段菜单区，而权限 122 在 5.7 节（约 1063 行）才定义，全新建库执行到菜单 205 时报 `ERROR 1452 (fk_sys_menu_permission)`。已将菜单 205 移至 5.8 节第二阶段菜单区（权限 122 之后）。
  2. 管理员数据范围种子（`sys_user_data_scope` id=1，ALL+WRITE）此前在本文件与 `sys_scope.sql` 中重复，按序执行报 `ERROR 1062` 主键冲突。已从本文件移除，该种子统一由 `sys_scope.sql` 提供。
- 对旧库影响：无。两处均为全新建库执行顺序问题，旧库数据不受影响；旧库无需任何操作。

### 2026-10-19 · 种子 · system 模块恢复 + booking 权限收紧

- 涉及文件：`sql/sys_rbac.sql`、`sql/lab_management_all.sql`、`sql/migrations/booking_flow_deploy.sql`（新增）、`sql/migrations/booking_deploy.sql`（新增）、`sql/migrations/booking_student_revoke.sql`（新增）
- 改动说明：
  1. `sys_rbac.sql` 整体替换为 release/0_1_1 完整版（397 行，27 个 system 权限），恢复此前缺失的 system 模块（用户/角色/组织/数据范围/操作日志/参数配置/助理授权）。
  2. `lab_management_all.sql` 模块六 booking 角色绑定改为 A 表形态：管理员 `booking:lab:list`(3002)+`booking:lab:approve`(3004)，老师 `create`(3001)+`list`(3002)+`cancel`(3003)，学生仅 `booking:lab:view`(3005) 只读；补菜单 3004（学生预约查询页）。
  3. dev/space 的 3 个脚本归档为旧库迁移：`booking_flow_deploy.sql` 的 3005/3004 内容已吸收进基线，其余两个（`booking_deploy.sql`、`booking_student_revoke.sql`）仅用于旧库升级。
- 对旧库影响：旧库执行 `sql/migrations/` 下对应迁移脚本即可，无需重建。

### 2026-10-18 · 种子 · 学生代理物料代领菜单

- 涉及文件：`sql/lab_management_all.sql`
- 改动说明：新增菜单 205 `ITEM_ASSISTANT_PICKUP`（物料代领，父菜单 151，绑定权限 122 `item:request:list`）。面向被老师授权的学生（学生代理），领取操作由后端按 `assistant_grant` 有效授权动态放行，未授权学生不可见/被拒。不新增独立角色。
