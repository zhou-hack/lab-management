# 数据库改动记录

记录本仓库每次数据库结构（DDL）与种子数据（DML）的改动，供组员同步本地库与审查使用。

## 使用规则

- 每次改动数据库后，在下方"改动明细"**倒序追加**一条（最新在最上）。
- 每条必须写清：日期、类型（结构/种子/迁移/修复）、涉及文件、改动说明、对旧库影响。
- 结构改动必须同步更新 `docs/数据库设计.md` 与 `sql/` 对应脚本，三者保持一致。
- 全新建库按序执行：`sys_rbac.sql` → `sys_policy.sql` → `assistant_grant.sql` → `lab_management_all.sql` → `sys_operation_log.sql` → `sys_scope.sql` → `sys_ops_role.sql` → `docx_seed_import.sql`。
- 旧库升级不重建，执行 `sql/migrations/` 下对应迁移脚本（幂等，可重复执行）。
- 编号段占用见文末速查表，新增种子数据先登记再使用。

## 改动明细

### 2026-10-19 · 结构+种子 · 需求 2.1 落地（节次/周期预约、砍盘点与价值追踪、权限层级、代理范围扩展）

- 涉及文件：`sql/lab_management_all.sql`、`sql/sys_rbac.sql`、`sql/assistant_grant.sql`、`sql/docx_seed_import.sql`
- 改动说明（依据 renew/需求2.1.md，6 项产品决策已定稿）：
  1. **节次预约**：新建 `class_period` 节次定义表（TIME(0) 上海本地，种子 1-8 节示例，部署前按学校作息调整）；`lab_booking` 新增 `booking_date`(DATE)、`start_period_id`/`end_period_id`（→ class_period）、`offering_id`、`course_name`、`class_name`；`start_at/end_at` 保留为由日期+节次推导的 UTC 值。
  2. **周期预约**：新建 `lab_booking_series`（固定星期+起止节次+使用周期，一次审批批量生成各周预约）；`lab_booking.series_id` 回指规则。
  3. **砍盘点**：删 `stocktake`/`stocktake_line` 两表，及权限 133-137、菜单 183 与动作 195-199、绑定 233-237/333/345-349，编号弃用不复用。
  4. **砍价值追踪**：`stock_balance` 删 `moving_average_price`；`stock_movement` 删 `value_delta/before_avg_price/after_avg_price`；`stock_document_line` 删 `unit_price_snapshot/amount_snapshot/adjust_direction`；`docx_seed_import.sql` 9-11 节同步去掉这些列。库存只记数量不记金额。
  5. **入库人/保管人**：`material_sku` 加 `first_inbound_user_id`（首次 OPENING 经办人，审计式不建外键）；`stock_location` 加 `custodian_id`（每库位一名，FK→sys_user）。
  6. **核销登记放宽**：`material_settlement.issue_line_id` 改可空，新增 `sku_id`/`location_id`，CHECK 二选一（关联原出库行 或 直填 SKU+库位）。
  7. **场地可见性**：`lab` 加 `visible TINYINT`（1可见/2不可见，CHECK；预约与查询列表只出 1）。
  8. **报修权限预留**：新增权限 160 `equipment:repair:create`、161 `equipment:repair:list`，绑定 529-532 授老师与学生（学生侧由后端按有效授权动态放行）；报修单表结构随"固定设备管理"章节落地。
  9. **权限层级**：角色 1 改名"实验室管理员"（role_code=ADMIN 不变）；system 模块全部权限/菜单不再绑定 ADMIN，移交 OPS_ADMIN（sys_ops_role.sql 动态绑定已有）；用户管理/名单管理并入新目录菜单 12"用户组"；TEACHER 保留助理授权三项（23-25）与助理管理菜单 11。
  10. **学生代理范围扩展**：`assistant_grant_scope` 范围类型加 `EQUIPMENT`（新增 `equipment_id` 列，恰一非空改三选一，归一生成列同步），动作加 `BOOKING`；equipment_id 外键已在整合基线模块三补充。
  11. **密码策略**：`sys_user.password_changed_at` 改为仅审计，不再强制 90 天更换（种子注释同步）。
- 对旧库影响：结构变更较多，旧库建议直接重建；不重建需自行 ALTER（加列/删列/删表/改 CHECK）并重跑受影响种子，本记录未提供迁移脚本。本地库已按新基线重建验证通过（40 表，全量导入成功）。

### 2026-10-19 · 修复 · 菜单 205 顺序错误 + 数据范围种子去重

- 涉及文件：`sql/lab_management_all.sql`
- 改动说明：
  1. 菜单 205 `ITEM_ASSISTANT_PICKUP`（物料代领）引用权限 122（`item:request:list`），此前误插在 4.9 节第一阶段菜单区，而权限 122 在 5.7 节（约 1063 行）才定义，全新建库执行到菜单 205 时报 `ERROR 1452 (fk_sys_menu_permission)`。已将菜单 205 移至 5.8 节第二阶段菜单区（权限 122 之后）。
  2. 管理员数据范围种子（`sys_user_data_scope` id=1，ALL+WRITE）此前在本文件与 `sys_scope.sql` 中重复，按序执行报 `ERROR 1062` 主键冲突。已从本文件移除，该种子统一由 `sys_scope.sql` 提供。
- 对旧库影响：无。两处均为全新建库执行顺序问题，旧库数据不受影响；旧库无需任何操作。
