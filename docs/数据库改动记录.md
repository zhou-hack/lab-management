# 数据库改动记录

记录本仓库每次数据库结构（DDL）与种子数据（DML）的改动，供组员同步本地库与审查使用。

## 使用规则

- 每次改动数据库后，在下方"改动明细"**倒序追加**一条（最新在最上）。
- 每条必须写清：日期、类型（结构/种子/迁移/修复）、涉及文件、改动说明、对旧库影响。
- 结构改动必须同步更新 `docs/数据库设计.md` 与 `sql/` 对应脚本，三者保持一致。
- 全新空库只执行 `sql/new_system_baseline.sql`；现行 22 表 `new_system/new_system_test` 追加物料模块时依次执行 `sql/item_material.sql`、`sql/migrations/item_assistant_pickup.sql`、`sql/migrations/item_location_responsible_history.sql`、`sql/migrations/item_location_code_reuse.sql`、`sql/migrations/item_notification_events.sql` 和 `sql/migrations/item_consumable_sku_clear.sql`；现行 39 表库先追加负责人历史迁移，现行 40 表旧结构库按需追加库位编码复用、通知事件及耗材 SKU 清理迁移。
- 其他旧库升级必须先核对目标库、前置结构和适用范围，再单独执行对应迁移；禁止批量执行旧 `migrations/`，禁止在 `lab_v0_1` 或 `lab_management` 执行现行脚本。
- 编号段占用见文末速查表，新增种子数据先登记再使用。
