规则要点：

1. **教师本人申请免初审**：提交即 APPROVED（写系统通过事件）。
2. **学生申请必须指定审批教师**（`approval_teacher_id` 必填），先经教师初审：通过即 APPROVED，驳回必填原因。
3. **价值分级已移除**（2026-10-22）：台账不再登记/展示价值分级，审批链为单级教师初审 + 管理员超时代批；`value_level_snapshot` 列零改表保留，新单恒为 NORMAL。
4. **一次一单对一台**：批量需求创建多张单据（表结构 `document_id` 唯一 + 一单一台已定稿）。
5. **数据范围**：学生/教师仅见本人申请（`applicant_id` = 当前用户）；教师初审待办按 `approval_teacher_id` = 当前教师；管理员见全部（部门级数据范围 `sys_user_data_scope` 二期细分）。

## 4. 核心流程清单

### 流程 A：设备使用申请与审批

| 步骤 | 角色 | 操作 | 状态/留痕 |
| --- | --- | --- | --- |
| 1 | 学生/教师 | 在「设备目录」选择在架设备，提交申请：用途、起止时间；学生须指定审批教师 | 创建 equipment_booking + biz_document（幂等键防重复提交） |
| 2 | 系统 | 按申请人分流 | 学生单 → `PENDING_TEACHER`；教师单 → 直接 `APPROVED` |
| 3 | 教师 | 初审学生单：通过 → `APPROVED`；驳回 → `REJECTED`（必填原因） | 事件留痕 document_event |
| 4 | 管理员 | 代批超时学生单（超 24h）：通过 → `APPROVED`；驳回 → `REJECTED`（必填原因） | 代批保存实际审批人（decided_by） |
| 5 | 学生/教师 | CHECKED_OUT 前可撤销本人申请 → `CANCELLED` | cancel_reason 留痕 |
| 6 | 系统 | **申请期放开时段互斥**（2026-10-23 起学生/教师可同时段申请同一设备）；审批通过（教师初审/管理员终审）时做**冲突校验**：同设备已存在相交时段 `[start_at, end_at)` 且状态 APPROVED/CHECKED_OUT 的单 → 拒绝；借出登记时同样先锁 asset 行再校验，实际占用先到先得 | 不自动抢占 |

超时策略（PRD 口径，二期自动化，一期先页面筛选超时单人工处理）：

| 环节 | 策略 |
| --- | --- |
| 学生单 PENDING_TEACHER | 4h 催办教师；超 24h 推送管理员可代批 |

### 流程 B：借出发放与归还登记（管理员经办）

| 步骤 | 角色 | 操作 | 状态/留痕 |
| --- | --- | --- | --- |
| 1 | 管理员 | 对 APPROVED 且已到时段的申请登记**借出发放**：锁 asset 行 → 校验设备 IDLE、无冲突占用 → 同事务建 equipment_usage（`CHECKED_OUT`，borrower=申请人、operator=管理员、due_at=end_at）并置设备 `IN_USE` | 使用记录 booking_id 唯一防重 |
| 2 | 管理员 | 归还登记：状态**完好** → usage `RETURNED`、单据 `RETURNED`、设备恢复 `IDLE`；状态**损坏** → 必填损坏描述（return_note）→ 设备置 `MAINTAINING` 转流程 C | operator 留痕 |

一期简化（与 PRD 差异，显式定稿）：借出/归还由管理员经办（代借代还），不做申请人自助确认与强制外观照（附件基建二期）；照片、DAMAGED 部位照等校验字段表结构已预留，二期补。

### 流程 C：归还损坏处理

1. 归还登记 DAMAGED → 设备立即 `MAINTAINING`（损坏描述留痕）；
2. 管理员线下维修，在现有台账体系回填处理结果：修复 → 恢复 `IDLE`；无法修复 → 走报废评估（现有 SCRAPPED 通道）；
3. `MAINTAINING` 长期未处理纳入审批页异常筛选（一期）与每日提醒（二期）。

### 流程 D：超期督办

| 超期时长（相对 due_at） | 处置 |
| --- | --- |
| 1 小时 | 提醒申请人 |
| 24 小时 | 升级提醒申请人、管理员 |
| 48 小时 | 冻结该用户未来 7 天申请权限（`user_booking_restriction` 表已建，固定 end_at，扫描重跑不得重复延长） |

一期：审批页提供「超期未还」筛选人工跟进；每小时定时扫描与消息推送二期实现。

### 与现有管理员维护流程的衔接（不变项 + 新增约束）

- 台账维护/迁移/导入导出权限与操作**全部不变**，仍仅 ADMIN；
- 迁移、删除仍仅允许 IDLE 设备；**新增**：`IN_USE`（借出中）设备不可删除、迁移、报废，不可再次借出（即使原单 end_at 已过）；
- 管理员代借代还同样不得跳过冲突校验（「老师普通免审批」也不得借用维修中或停用设备）。

## 5. 状态机速览

### 5.1 使用申请单（equipment_booking.status）

```
学生单：PENDING_TEACHER ──教师通过──> APPROVED
教师单：提交即 APPROVED（系统通过事件）
APPROVED ──管理员登记借出──> CHECKED_OUT ──管理员登记归还──> RETURNED
PENDING_TEACHER ──驳回──> REJECTED（必填原因）
PENDING_TEACHER ──超 24h 管理员代批──> APPROVED / REJECTED
APPROVED 之前（含待审与已批未借出）──申请人撤销──> CANCELLED
```

### 5.2 设备（equipment_asset.status）

```
IDLE ──借出登记──> IN_USE ──归还完好──> IDLE
IN_USE ──归还损坏──> MAINTAINING ──管理员回填修复──> IDLE
MAINTAINING / IDLE ──报废──> SCRAPPED（终态）
```

一期不启用 RESERVED：申请期不预占资源（2026-10-23 起学生/教师可同时段申请同一设备），审批通过与借出登记时校验冲突，借出登记才锁定设备状态。
