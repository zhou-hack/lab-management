# 高校场地管理节次体系调研与二期功能排期

> 整理日期：2026-10-28 ｜ 依据：国内标杆高校场地/教室资源管理系统的通行公开实践（教务处教室管理规范、场馆预约系统公开说明）整理提炼
> 用途：① 作为本期「节次体系重设计 + 表格化/日历视图替换」的设计基线；② 承载教师端 7 项、学生端 8 项增强功能的二期排期方案

---

## 一、标杆高校节次安排方案要点

### 1. 清华大学（教室资源统一管理）

- **节次划分**：全天 1~13 节，每节 45 分钟 + 课间 10 分钟；上午 1-4 节（08:00 起）、下午 5-9 节（13:30 起）、晚上 10-13 节（18:30 起），末节 21:55 结束
- **时间粒度**：最小预约单位为「节」，排课按「大节连排」（1-2 节、3-4 节成对）；临时借用允许单节
- **冲突校验**：教室-日期-节次三维互斥；排课数据与临时借用数据合并判定，端点相接不算冲突（半开区间）
- **特殊时段**：考试周由教务处统一锁定教室排考，锁定期间借用申请自动驳回；节假日按校历关闭预约入口；大型活动（校庆、开学典礼）由管理员批量封锁并提前公示

### 2. 浙江大学（场馆/会议室预约）

- **节次划分**：固定节次 + 自由时段双轨——教学场所按节次，会议室/研讨间按 30 分钟粒度自由时段
- **时间粒度**：30 分钟（研讨间）/ 单节（教室）；跨时段申请自动拆分为最小粒度校验
- **冲突校验**：提交预检 + 审批复核双道；同场地同时间窗口重叠即拒绝，审批时二次复查（防提交后状态漂移）
- **特殊时段**：假期开放规则切换（暑期仅开放部分楼栋）；考试季场馆用途变更需管理员审批联动

### 3. 华中科技大学（多校区教室管理）

- **节次划分**：分校区差异化节次表（主校区与分校区上下课时刻不同）；晚间节次按季节微调
- **冲突校验**：申请人提交即见冲突明细（哪一节被谁占用）；批量申请（整学期每周固定）逐周预检、一次性反馈冲突周清单
- **特殊时段**：节假日调课与校历联动——调休工作日按被调日期的节次表执行；封楼/消杀时段由管理员按楼栋批量设置不可用
- **信用机制**：预约未使用且未取消记违规，累计影响后续预约资格（违规公示于院系）

### 4. 高职院校实训室通行做法（与本校场景最近）

- **节次划分**：实训课以「2 节连排」为最小教学单元（90 分钟一次实训），全天 12 节覆盖 08:00-21:45
- **冲突校验**：实训室同时关联「配套设备/工位数」，冲突判定叠加容量与工位约束
- **特殊时段**：技能竞赛集训期、考证周由实训中心统一预留场地，期间暂停日常预约

## 二、设计要点提炼 → 本系统映射

| 高校通行要点 | 本系统现状 | 本期落地 | 二期方向 |
| --- | --- | --- | --- |
| 节次=45 分钟+课间，覆盖早 8 点至晚 21:45 | class_period 12 节固定种子（08:25-21:45） | 节次可自定义时长/启停/批量生成（管理员维护） | 分场地类型差异化节次表 |
| 大节连排（2 节为教学单元） | 起止节次区间连续选择已支持 | 表格矩阵内点选两格成区间，沿用 | 一键选「大节」（1-2/3-4…）快捷按钮 |
| 三维互斥 + 半开区间 + 双道校验 | lab_slot 半开区间 + 提交预检 + 批准行锁复查 | 不变（已符合） | 叠加课表数据（course_schedule） |
| 节假日/考试周/大型活动调整 | 无（节次全局恒定） | 节次管理界面可临时停用节次 | 场地封锁日历（按日期范围批量不可用） |
| 表格化课表式展示 | 横向节次卡片时间轴 | **替换为：日矩阵（节次×场地）+ 周日历（节次×星期）组合** | 学期总课表导出 |
| 批量时段设置 | 无 | batch_generate 一键重建节次序列 | 按学期/校区多套节次方案切换 |

## 三、二期功能排期（教师端 7 项 + 学生端 8 项）

> 数据库授权已获批准（2026-10-28）：允许新增表与权限种子。以下按依赖关系排序，建议分两批实施。

### 批次一（权限与预约链路扩展，预计先行）

| # | 功能 | 要点 | 主要变更面 |
| --- | --- | --- | --- |
| T1 | 学生预约权限开放 | 学生可申请（社团集体预约表单：社团名/指导教师/人数证明附件），仍走管理员核对；反转一期只读约束 | sys_permission/role_permission 种子、userType 兜底放开、申请表字段 |
| T2 | 教师绿色通道 | 教学计划内课程关联预约免审批直批（与课表/开课清单联动） | 审批分支、课程白名单表 |
| T3 | 临时调课场地申请 | 关联原预约单，审批通过后自动改签（原槽释放+新槽写入） | 改签事务、事件类型 CHANGE |
| S1 | 预约成功消息推送 | 站内通知表 + 轮询/推送通道；审批/取消/强取消全事件触达 | notice 表、前端消息中心 |
| S2 | 预约取消规则提示 | 取消弹窗展示规则文案（时限/违规计数影响），从策略表读取 | 前端组件 + policy 配置 |

### 批次二（使用闭环与信用体系）

| # | 功能 | 要点 | 主要变更面 |
| --- | --- | --- | --- |
| T4 | 师生自助签到/签退 | 当前为管理员代签到清点；改为申请人到场扫码/定位自助签到，签退写评价入口 | CHECKIN 操作人放开、签到凭证 |
| T5 | 名下预约一键管理 | 我的预约批量取消/批量延期入口 | 前端批量操作 + 后端批接口 |
| T6 | 节次冲突自动提醒 | 提交前预检冲突时给出「相邻空闲节次」替代建议 | availability 推荐算法 |
| S3 | 使用签到验证 | 签到凭证（动态码）防代签 | 与 T4 合并实施 |
| T7/S4 | 预约历史导出统计 | 个人维度 CSV 导出 + 使用时长统计图 | 导出接口放开个人范围 |
| T8 | 场地使用评价反馈 | 使用后评分+留言，管理员可回复；新表 lab_review | lab_review 表 + 审核流 |
| S5 | 违规预约记录公示 | 未使用未取消自动记违规，看板公示脱敏名单；策略表控制阈值 | violation 表 + 公示只读接口 |

### 依赖与约束说明

- T1 是学生端其余功能的前置；S1 消息中心建议随 T1 同批（学生首登即有通知诉求）
- T4/S3 合并为一次「自助签到」改造，避免事件模型两次变更
- 违规公示（S5）依赖签到数据积累，最后实施
- 全部新表沿用既定类型记号与 UTC 约定；权限码沿用 `模块:资源:操作` 规范
