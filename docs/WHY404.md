# 刷新页面 404 问题修复记录

**日期**：2026-10-16
**影响范围**：前端全部动态注册的业务页面（系统管理、设备、场地、预约、物料等）
**修复提交文件**：`frontend/src/router/index.js`

## 一、故障现象

已登录状态下，在任意业务页面按 F5 刷新（或在地址栏直接回车冷启动），页面稳定落到「404 页面不存在」，必须回到首页重新点菜单才能进入。静态首页 `/admin/home` 刷新正常。

## 二、根因分析

本项目为 SPA + 动态路由：静态路由只登记布局与登录页，业务页面路由在登录后由 `router/dynamic.js` 按后端菜单的 `componentKey` 白名单调 `router.addRoute` 挂到 `AdminLayout` 下。刷新时动态路由尚未注册，依赖全局守卫 `beforeEach` 先拉取菜单、注册路由，再重放目标地址完成匹配。

故障链有两环，缺一不可：

1. **兜底路由用 `redirect` 写法，原始目标路径在匹配阶段就被吞掉**
   修复前兜底为 `{ path: '/:pathMatch(.*)*', redirect: '/404' }`。Vue Router 的 `redirect` 在**路由匹配（resolve）阶段**就执行，早于一切守卫。刷新 `/admin/system/user` 时动态路由未注册，命中兜底记录并立即重定向，守卫拿到的 `to` 已经是 `/404`——原始路径 `/admin/system/user` 在进入守卫前就已永久丢失。

2. **守卫重放的是已被改写的 `to`**
   守卫拉完菜单、注册动态路由后执行 `return { ...to, replace: true }` 重放，此时 `to.path` 已是 `/404`，于是"正确地"导航到了 404 页。动态路由虽已注册，却再没有人导航回原始地址。

时序如下：

```
刷新 /admin/system/user
  → 匹配：动态路由未注册，命中 /:pathMatch(.*)* 
  → redirect 在匹配阶段执行，location 被改写为 /404   ← 原始路径丢失点
  → beforeEach(to=/404)：拉菜单、addRoute（此时 /admin/system/user 已可匹配）
  → return {...to, replace:true} 重放 /404            ← 错误放大点
  → 停在 404 页
```

## 三、修复方案（`frontend/src/router/index.js` 两处）

1. **兜底 404 改为直接渲染组件，不再 redirect**：
   `{ path: '/:pathMatch(.*)*', component: NotFound, meta: { title: '页面不存在' } }`。
   未匹配时 URL 保持原样（这也是 SPA 常见形态），守卫因此能在 `to.fullPath` 中拿到真实目标路径。原显式 `/404` 命名路由无其他引用，一并收敛删除。

2. **守卫重放改为 `return to.fullPath`**：
   用完整路径字符串（含 query/hash）触发新一轮导航；不再使用 `{ ...to }` 展开，避免 `to` 命中兜底记录时携带其记录信息（name 等）造成解析二义性。

修复后时序：

```
刷新 /admin/system/user
  → 匹配：命中兜底 404 记录（不 redirect，to.fullPath 仍为 /admin/system/user）
  → beforeEach：拉菜单、addRoute
  → return to.fullPath 重放 /admin/system/user
  → 新一轮匹配命中刚注册的动态路由，正常渲染
```

## 四、验证结果（浏览器实测）

| 冷启动直进 | 地址栏直输 `/admin/equipment/model` | 正常渲染型号管理页 |

前端 `npm run lint`、`npm run test`（33 用例）、`npm run build` 全部通过。

## 五、防复发约定

- **兜底 404 路由禁止用 `redirect` 写法**，一律直接渲染 NotFound 组件；凡是"守卫里注册路由后重放"的动态路由架构，重放目标必须来自未被改写的 `to.fullPath`。
- 动态路由注册完成后的重放只传路径字符串，不用 `{ ...to }` 展开对象。
- 后续新增布局壳或调整守卫时，必须回归验证两个场景：动态页面 F5 刷新、地址栏冷启动直进动态路由页。
